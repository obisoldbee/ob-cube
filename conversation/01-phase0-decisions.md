## 关键分叉：纯前端 vs 带后端

附件草稿提出"隐藏状态必须由数据访问层执行，而非 CSS 遮挡"，并列出服务端强制观察权限、API 认证、请求限流、操作幂等等要求。这与用户原话"请实现完整的前端界面与交互逻辑"存在张力。

**裁决：纯前端，不做后端。**

理由：
- 用户明确要求交付的是前端界面与交互逻辑，未提出账号、云端题库或多人协作需求。
- 本产品是单机评测工具，题目在本地生成、成绩在本地存储，不存在多租户数据隔离需求。
- 引入后端会让"下载即用、静态托管"的交付形态丢失，收益与成本不匹配。

**代价（必须如实记录）**：观察权限门控只能在 API 层实现，无法构成安全沙箱。用户仍可通过 DevTools 读内存或改源码绕过。这条边界会在 PRD 中明示，不以"防作弊"为卖点宣传。

## 已锁定决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 技术栈 | Vite + TypeScript + Three.js | 真 3D 渲染与层转动动画；引擎与 UI 分层，人类按钮与 Agent API 调同一引擎实例 |
| Agent 接入 | 页面内 `window.cubeAgent` JS API | 与按钮同源，Playwright / DevTools / 浏览器类 MCP 可直接调用，无需常驻进程 |
| 界面主题 | 深色竞技风 | 魔方六色在深底上辨识度最高，符合速拧计时器的专业观感 |
| 交付形态 | 可 `npm run build` 出静态站点 | 无服务端依赖 |

## 沿用附件草稿的核心约束

- 人类与 Agent 共用同一套魔方规则与操作引擎。
- 视觉展示、真实状态、Agent 观察权限三者独立。
- 每次转动可验证、可记录、可复现。
- 默认不向 Agent 暴露隐藏状态、预生成答案或未授权的完整数据。
- 计步默认 HTM（`R` / `R'` / `R2` 各计 1 步），视角旋转不计步。

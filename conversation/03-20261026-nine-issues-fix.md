# 03 · 2026-10-26 九条用户反馈的裁决与修复

## 输入

用户 2026-10-26 反馈九条（Agent可选 / 倒计时可选 / 再挑战与步数上限 / 转向随机 / 层转说明 / 蒙层可选 / 可选题目 / 暂停无效 / 超时不置灰）+ 录屏 `material/202610251133/20261025-233326.mp4`（29s，2fps 拆帧 59 张，双子代理视觉分析）。

## 裁决

全文见 `docs/decisions/2026-10-26-nine-issues-ruling-decision.md`；PRD 同步升 **v1.9**，SPEC 升 **v1.1**。要点：

1. **暂停改真暂停**（推翻 v1.2"计时不暂停"）：elapsed=活跃时长，暂停中不可能超时，画面遮蔽防观察，结果记录 pause_count/paused_total_ms。
2. **预观察模式**：蒙尘=关（默认）时 ready 可见题面+可转视角；API observe 门控不放开；rotateView 前置条件加 ready。
3. 时限默认改**不限时**；配置入口进页面（左栏挑战配置面板）；URL 参数优先。
4. 参与者=人类（默认）隐藏 Agent 面板；`window.cubeAgent` 恒挂载。
5. 再挑战一次=新题面回 ready；同题面重跑=同题面回 ready；均不自动起表。
6. F15 最小题库（6 条 seed 锚定预设）提前落地。
7. AC-28 补"超时迁移 200ms 内全页禁用置灰"。
8. 归并第二次按键执行**同向 90°**（规格澄清，修正实现偏差）。

## 实现与根因（关键三条）

| 现象 | 根因 | 修复 |
|---|---|---|
| 转向"随机/反转" | 双击归并时第二击被提交为 amount=2（180°），两击合计 270°=反向 90°；且归并从不成立（记法对不上） | keyboard：第二击保持 baseAmount 同向 90°；session：按共同 amount 合并计步（X 与 X' 双击均可归并为 X2） |
| 超时不置灰 | rAF 循环只刷计时数字不调 `session.tick()`，状态机要等下一次操作才迁移 | 循环内 tick + 状态变化即 sync；矩阵 setEnabled 同帧锁定（按钮真 disabled） |
| 再挑战无效 | 按钮绑到 `startChallenge()`，ended 态下 `start()` 静默 return | 新增 retryNew/rerun 端口，行为按裁决定义 |

修复过程中额外发现并修掉：log 面板差分键只看条数导致归并行显示旧值（R2 显示成 R）；步数耗尽不在第 N 步立即结算；`.panel` 作者样式覆盖 hidden 属性；aria-disabled 连坐禁用说明按钮；config 面板 timeLimitSec/ms 字段未换算。

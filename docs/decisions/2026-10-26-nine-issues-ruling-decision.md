# 裁决：2026-10-26 用户九条反馈的需求整理与处置

> 输入：用户 2026-10-26 反馈九条 + 录屏 `material/202610251133/20261025-233326.mp4`
> 核对基线：PRD v1.8 / UIUX v1.2 / SPEC v1.0 / 实现 `src/ob-cube@dist(10-25)`
> 结论：3 条为实现偏离（PRD 已有、代码没做对），4 条为 PRD 缺口（本轮补齐），
> 1 条为 PRD 明文裁决与用户期望冲突（按用户新裁决推翻），1 条为 UX 说明缺失。
> 本文件是本轮修复的需求基线；PRD 同步升 v1.9。

## 逐条处置

### 1. Agent 接入是可选项，不是必须项

- 用户期望：人在玩的时候，Agent 会话面板不要一直"检测 Agent 调用"。
- PRD 现状：`参与者` 配置已有（PRD §2.2），但只影响"是否默认聚焦 API 面板"；
  UIUX §7.6 把 Agent 会话区块定义为常驻。实现里 Agent 面板恒显示
  "尚未检测到 Agent 调用"。
- 裁决：**参与者=人类（默认）时隐藏右栏 Agent 会话面板**；切到"AI Agent"才显示。
  `window.cubeAgent` API 恒挂载不变（AC-41 不受影响，它约束的是 API 形态，不是面板可见性）。
- PRD 变更：§2.2 参与者行、UIUX §7.6。

### 2. 倒计时可选、可调，不写死

- PRD 现状：时限本就可配置（不限时/60s/3min/5min/20min/自定义，默认 20min，PRD §2.2）。
- 实现缺口：只支持 URL 参数 `?time=`，页面没有任何配置入口——用户视角等于"写死"。
- 裁决：**新增页面内"挑战配置"面板**（左栏，待开始/已结束时可编辑）：
  时限 = 不限时（新默认）/ 2min / 5min / 20min / 自定义秒数（10s~180min）。
  默认值从 20min 改为**不限时**：计时器默认只计上行时间，倒计时仅在被明确配置后出现。
  URL 参数仍然生效且优先级高于本地设置。
- PRD 变更：§2.2 时间限制行（默认值改"不限时"）。

### 3a. "再挑战一次"无效

- 根因（实现 bug）：结果面板"再挑战一次"与左栏 ended 态按钮都绑到 `startChallenge()`；
  会话结束后 `session.start()` 的前置守卫静默 return，点击等于没点。
  "查看回放"走独立端口所以正常。
- 裁决（同时补齐 PRD 行为定义空白）：
  - **再挑战一次** = 保留当前配置，生成**新题面**，回到 `ready`（不自动开始）。
  - **同题面重跑** = 同一题面重置状态/计时/计步/日志，回到 `ready`（不自动开始）。
    （旧实现"重跑即自动开始计时"一并废除——计时起点必须由玩家显式按下。）
  - 两者都终止进行中的回放，清掉结果面板。
- PRD 变更：§9.1 操作区行为定义（原来只有按钮名与埋点）。

### 3b. 步数上限可选

- PRD 现状：`步数限制 = 不限步/20/50/100/200/自定义，默认不限步`（§2.2），
  判定规则完整（§7.3：第 move_limit 步执行完仍未还原才判负，还原优先）。
- 实现缺口：引擎与判定已支持（E_MOVE_LIMIT_REACHED），但 UI 没有配置入口。
- 裁决：进 3a 的同一个"挑战配置"面板：不限步（默认）/ 20 / 50 / 100 / 自定义（≥1）。

### 4. 转向"随机/反转"——实现 bug，规格本身无冲突

- 根因（代码与 SPEC §11 坑 1 / PRD §5.4 v1.2 第 5 条的直接违背）：
  双击归并时，第二次按键被提交为 `amount=2`（180°）。
  快按两下 = 90° + 180° = **270° = 反向 90°**；四次 = 540° ≠ 复原。
  且 `mergeLastIntoDouble` 期望读到两条 90° 记录，实际读到 180°，
  归并从不成立——计步也没合并。时快时慢导致有时落在 300ms 窗口内有时不在，
  用户观感即"随机"。
- 修复（回归规格本意）：
  - 第二次按键照常执行**同向 90°**（`amount` 与第一次相同）；
  - 归并只发生在「同面 + 同层 + 同转向量」两次连按（Shift 双击= X' X' → X2 也合法）；
  - 会话层把两条 90° 事件合并为一条 X2（1 步，`merged_from` 保留）。
  - 键盘映射本身是固定映射（D=R 面，AC-31），与视角无关，不改动。
- 连带修复：`设置.mergeDoubleTap`（PRD §2.2"键盘 180° 双击归并 开/关"）此前从未接线，
  本轮接入：关闭后双击就是两次独立 90°（2 步）。

### 5. 单层/双层/宽转区别——UX 说明缺失

- PRD 现状：记法与 tab 定义完整（§5.3.2、§3.4），但没有要求 UI 解释。
- 裁决：按钮矩阵 tab 栏右侧加**说明 icon（lucide info，SVG，合规 AC-54）**，
  点击弹出说明浮层：单层 / 中层 / 宽转2 / 宽转3 / 内层 / 自由层各自的含义、
  记法示例（R / M / Rw / 3Rw / 2R）、键盘前缀（1/2/3/Z/C）。
- PRD 变更：UIUX §4.2 补一条。

### 6. 蒙层可选：允许"先看再开始"（预观察模式）

- PRD 现状：蒙尘开/关已有（§2.2，默认关），但 C1~C5 把 ready 态写成无条件遮蔽 +
  observe 无条件拒绝；没有"开始前看题面"的 inspection 概念。
  实现把 ready 恒蒙尘，等于把"开"焊死。
- 裁决（对齐国际比赛"先观察、再起表"的直觉）：
  - **蒙尘=开**：ready 态遮蔽（现状语义，C1~C5 全部维持）。
  - **蒙尘=关（默认）**：ready 态直接显示打乱后的真实颜色，可自由旋转视角观察，
    计时从按下"开始挑战"起算——即预观察模式。
  - API 门控不因预观察放开：ready 态 `observe()` 仍拒绝（AC-14 不变）。
    预观察是给"人眼"的，不是给 Agent 的读数通道；Agent 评测请配置蒙尘=开。
  - ready 态文案随模式切换：开=原 C5 文案；关="预观察模式：开始前可自由查看题面，
    计时从按下开始挑战起算。"
  - 连带：ready 态允许视角旋转（方向键/面视按钮/复位）。
    `rotateView` 的 API 前置条件从 `running|solved_pending` 放宽为
    `ready|running|solved_pending`（视角不是颜色数据，不破 AC-14/AC-64）。
- PRD 变更：§2.2 蒙尘行、§8.2 C2/C5 增加条件、§6 API 表 rotateView 行、SPEC §6。

### 7. 可选题目

- PRD 现状："固定题目（从本地题库选）"已定义但标 P1（F15）。
- 裁决：**v1.1 提前落地最小题库**：内置预设题（2/3/4 阶各 2 条，seed 锚定、
  可复现、带标签），配置面板里"题目"下拉 = 随机（每次新题）/ 预设 6 条 /
  指定 seed 输入。云端题库、导入导出仍在范围外。
- PRD 变更：F15 由 P1 调整为 v1.1 最小实现（本地预设 + 指定 seed）。

### 8. 暂停应真正暂停

- PRD 现状：§7.2.1 明文裁决"计时不暂停、只屏蔽输入"（AC-55~60），理由是人机公平。
- 用户裁决（2026-10-26，推翻上表）：**暂停 = 冻结计时 + 屏蔽输入 + 冻结画面**。
- 新语义（P1'~P7'）：
  - P1' 暂停期间 `elapsed_ms` 冻结（elapsed = 活跃时长，扣掉暂停段）。
  - P2' 超时判定基于冻结后的 elapsed，暂停中不可能超时（原 P2/P3 作废）。
  - P3' `paused` 期间 observe/applyMove/submitSolution/rotateView 返回 `PAUSED`
    （错误码实现口径 `E_CHALLENGE_PAUSED`）。
  - P4' 暂停仍仅人类模式可用；`cubeAgent` 不暴露 pause/resume（不变，AC-58 保留）。
  - P5' 每次暂停/恢复记事件（不变，AC-60 保留）。
  - P6' 结果必须记录 `pause_count` 与 `paused_total_ms`，结果页显示
    "本次运行包含 N 次暂停（共 M 秒），计时已扣除。"（AC-59 改写）
  - P7' 暂停时 3D 冻结 + 遮罩 + 倒计时数字**冻结**（与旧 P7 相反）。
  - 公平性补偿：暂停期间 3D 画面被遮罩盖住（沿用 paused 遮罩规范 UIUX §7.7.2），
    暂停不能当"无限观察"用；评测对比时 `paused_total_ms` 是显式可见的口径差异。
- PRD 变更：§7.2.1 整节重写、§7.3 超时行、§8.5、AC-55~57/59 改写、UIUX §7.7。

### 9. 倒计时结束后立即置灰

- 根因（实现 bug）：主渲染循环只刷计时数字，不调 `session.tick()`；
  超时只在下一次用户操作（applyMove 入口 tick）才被判定——于是"按一下才禁止"。
- 修复：渲染循环每帧 `tick()`，状态一旦迁移立即全量同步 UI：
  舞台进 ended（降饱和）、按钮矩阵 aria-disabled + 置灰、键盘输入通道关闭、
  右栏切结果面板。动画播完后定格（§7.3 原文行为保留）。
- PRD 变更：AC-28 补一句 UI 立即禁用的验收（原 200ms 口径保留）。

## 不改的东西（防跑偏）

- 计步口径 HTM、归并是输入整形不是计步规则（§5.4 裁决不变）。
- `window.cubeAgent` 九方法白名单、snake_case、错误码族（AC-41~48 不变）。
- 观察模式五档、还原判定、指纹与复现机制。
- drag-to-turn、移动端、后端仍不做。

## 验收清单（本轮修复完成定义）

1. 人类模式默认看不到 Agent 面板；切"AI Agent"后出现并恢复检测显示。
2. 配置面板可切 不限时/2min/5min/20min/自定义；倒计时条只在有限时出现。
3. 步数上限 不限/20/50/100/自定义；到限未还原判负（ended_move_limit）。
4. D D 快按 = 一次 180°、计 1 步；D D + D D = 复原；Shift+D 双击同理。
5. tab 栏有说明 icon，弹层解释六类层转。
6. 蒙尘关：ready 可见彩色题面 + 可转视角 + 预观察文案；蒙尘开：维持遮蔽 + C5 文案。
7. 题目下拉可选随机/6 条预设/seed 输入；预设可复现（同 ID 同指纹）。
8. 暂停后倒计时冻结、画面遮罩；继续后恢复；结果页显示暂停次数与总时长。
9. 倒计时到 0：≤200ms 内全页置灰禁操作，无需再按一次。
10. "再挑战一次"→新题面 ready；"同题面重跑"→同题面 ready；两者都在结束后可用。

# ADR-006：TypeScript 从 `~7.0.2` 回退到 `~5.9.3`

## Status

Accepted（回退实际发生于 2026-10-25/26；**本 ADR 补记于 2026-10-26**，见下方「补记说明」）

## Context

原 `SPEC-v1.0.md` §4「技术架构（锁定 — 版本锚定）」把 TypeScript 钉在 `~7.0.2`，并**显式写了一条回退分支**：

> | 语言 | typescript | `~7.0.2` | 若 `tsc --noEmit` 报编译器级不兼容，回退 `~5.9.3` 并记 ADR |

同一份文档的 §11「内嵌已知坑」第 6 条也预判了这个坑：

> | 6 | TS 7 下 `@types/three` 报类型错 | 类型包声明 `typeScriptVersion: 5.6` | 先降 `typescript` 到 `~5.9.3`，再考虑局部 `@ts-expect-error` 并记 ADR |

**回退分支已经实际触发**：`src/ob-cube/package.json` 的 `devDependencies.typescript` 现为 `~5.9.3`，`npm run typecheck` 零错误。根因如坑 #6 所预判——`@types/three@~0.186.0` 在其 `package.json` 里声明 `typeScriptVersion: 5.6`，与 TS 7 的类型系统不兼容。

## Decision

采用回退分支：**`typescript` 锚定 `~5.9.3`**，不使用 `~7.0.2`。

不采用"局部 `@ts-expect-error`"这条备选路径，理由：

1. `@ts-expect-error` 会**吞掉该行的全部类型错误**，包括未来真正引入的错误。three 是本项目的核心依赖（渲染层全部建立在它之上），在它周围散布抑制注释等于把渲染层置于类型检查之外。
2. 报错源头是**第三方类型包的版本声明**，不是本项目代码有问题。用抑制注释去绕过上游的版本声明，是把上游的债务转成本项目的债务。
3. 回退到 `~5.9.3` 是 SPEC 自己预设的第一顺位方案，`tsc --noEmit` 零错误已验证可行，无残留代价。

## Consequences

**正面**

- `npm run typecheck` 零错误，`npm run build`（`tsc --noEmit && vite build`）通过。
- 与 `@types/three@~0.186.0` 的 `typeScriptVersion: 5.6` 声明兼容，无需任何类型抑制注释。
- 其余版本锚定全部未受影响：`vite ~8.3.5`、`three ~0.186.1`、`@types/three ~0.186.0`、`vitest ~5.0.5`、`@vitest/coverage-v8 ~5.0.5`、`jsdom ~30.1.3`、`lucide-static ~1.61.0`。

**负面 / 需要跟踪**

- 放弃了 TS 7 的语言特性。对本项目影响很小——代码库不使用任何 TS 7 独有语法，`tsconfig.json` 也未启用相关选项。
- 未来若要升回 TS 7，前置条件是 `@types/three` 更新其 `typeScriptVersion` 声明。这是一个**外部依赖**，本项目无法自行推进；升级时机由上游决定。
- 需要在 `execution/CONTRACT.md` §1 的版本锚定表里把 `~7.0.2` 更正为 `~5.9.3`，否则下次有人照文档装依赖会重新踩坑。

## 补记说明（为什么这份 ADR 迟到了）

SPEC §4 的回退分支要求"回退 `~5.9.3` **并记 ADR**"。回退被执行了，ADR 没有写——`ADR-001`~`ADR-005` 覆盖的是 facelet 状态模型、程序化置换、整体旋转只转相机、纯前端交付、cubie mesh 渲染，**没有一条涉及 TypeScript 版本**。

这是 2026-10-26 的文档矛盾排查中发现的，属"活规格纪律"的一次失守：文档规定了动作与记录义务，动作做了、记录漏了，于是下一次读文档的人看到的是"锚定 `~7.0.2`"，而 `package.json` 里是 `~5.9.3`，两者无从对账。

**防复发措施**：`docs/specs/execution/CONTRACT.md` 的 v2.0 修订说明第 4 条已登记此事；`docs/specs/prd/11-appendix.md` 附录 B 的一致性自查表新增了一条"文档是否声称了代码没有的能力"的自查项，同类"文档规定 X、代码是 Y、无人记录"的漂移应在每次 PRD 升版时被这条自查捕获。

# ADR-002：转动置换由几何算法程序化生成，禁止手写置换表

## Status

Accepted（2026-10-25）

## Background

魔方引擎的正确性几乎全部压在「一次转动如何重排贴纸」这件事上。常见做法是查表：为每种记法手写一个 `number[]` 置换数组。

这种做法的风险在本项目被放大到不可接受的程度，原因是三个规模的乘法：

- 3 个阶数（2/3/4）
- 每个阶数约 36 / 81 / 126 条合法单步（含内层、宽转、区间形式）
- 每条单步 3 种后缀

手写意味着数百个数组、上万个元素。而这类错误的特点是**静默**：数组长度对、类型对、程序能跑、魔方也能转，只是某个面反了或者某两层换了位置。它不会被编译器发现，也不会被「能转」这类冒烟测试发现，只有对着真实魔方逐个核对才会暴露。

PRD 4.3 要求「根据阶数动态生成可操作层数」，本身就暗示了参数化而非穷举。而本产品还有一个额外的放大器：**历史题目靠重放打乱序列复现**。如果置换表有一处错，所有历史题目的初始状态都会与记录不符，且不会有人发现——直到有人拿同一个 seed 复现出两个不同的局面。

## Decision

**置换必须由几何算法程序化生成。代码中不存在任何手写的 (slot → slot) 置换数组。**

允许手写的只有一张 6 行的「面 → 外法向量 + 局部基向量」表，即 `engine/geometry/face-layout.ts`。它定义坐标系，不是置换；置换由它推导。

生成算法：

1. 为每个 facelet 记录唯一的三元组 `(face, row, col)` 及其 `(pos, normal)`，`pos` 用**双倍整数坐标** `c(i) = 2i - (N-1)` 表示，`pos = n·(N-1) + u·c(col) + v·c(row)`。
2. 建立 `(pos, normal) → slot` 的哈希索引，`6N²` 个键，构造时断言无重复。
3. 一次转动定义为 `(axis, A, k)`：轴、轴索引集合、四分之一转次数。对每个 `pos[axis] ∈ A` 的 facelet，把 `(pos, normal)` 旋转为 `(R·pos, R·normal)`，用索引反查目标 slot，令 `perm[target] = source`。
4. 旋转只用整数 `ROT90`（元素仅取 `0/±1`），引擎侧全程零浮点。

正确性由四条引理保证（已写进代码注释）：

1. `ROT90` 是行列式 +1 的整数正交矩阵，立方体外表面片集合在其作用下封闭。
2. 映射 `slot ↦ (R·pos, R·normal)` 在全体 slot 上是双射（`R⁻¹` 给出逆）。
3. 该映射保持沿转轴的分量不变，因此每个层子集在映射下封闭。
4. 由 2、3 得 `perm` 在每个层子集上双射、子集外恒等，故整体双射；又 `R⁴ = I`，故阶整除 4。

层号到轴索引的换算是一条规则而非六张表：正侧面 `a = N - l`，负侧面 `a = l - 1`；方向 `k = 3` 在正侧、`k = 1` 在负侧（顺时针从面外看）。

## Consequences

正面：

- 实现量从「数百个数组」降到「约 120 行生成器 + 6 行几何表」，两者都可被完整审查。
- 3 阶与 4 阶不需要任何专用代码，`N` 是唯一参数；新增 5 阶只需放开 `N` 的枚举与层数上限。
- 置换的正确性可以被**机器证明**而不只是「看起来对」：双射、阶整除 4、逆元、受影响 slot 计数、循环结构，五条性质全部可断言（见 ARCHITECTURE §4.6）。
- 受影响 slot 计数有一条闭式：`Σ_{a∈A}(4N + (a 为外层 ? N² : 0))`。这条式子同时校验了「层集合换算」与「几何邻接」两件事，是意外收获。
- 静默错误的检测从「人工核对」变成「CI 里必然红」。

负面与代价：

- **性能略差于查表**：单步是 `O(6N²)` 次整数操作（4 阶 96 次），而查表是 `O(6N²)` 次拷贝。实测差异在纳秒级，且只在每步执行一次，不构成问题。用缓存 `(N, axis, a, k)` 后（条目数 ≤ 36），首次之后的成本与查表相同。
- **几何表写错会同时影响所有阶数**。这是一处单点故障，必须由 T-01（`u × v = -n`）与 T-08（六面搬运方向）共同锁住。相比「手写表里错一个元素」，这是更小的故障面，但仍需正视。
- **`cross(u,v) = -n` 这条约束需要解释**。它的含义是「局部行方向朝下」的屏幕基约定。如果不写清楚，后来者按直觉改成 `+n` 会导致所有面的颜色矩阵镜像。必须在 `face-layout.ts` 顶部用注释固定这条约定。

验证记录（用于日后判断「这条纪律是否真的有效」）：

- 生成器已用临时脚本在 2/3/4 三个阶数上做过 106 条性质断言，全部通过；其中包含对 2 阶 `2R = L'`、3 阶 `2R = M'`、4 阶 `2-3Rw = 2R∘3R` 三条跨阶数恒等式的实测。
- 已实测的受影响 slot 数与循环结构：2 阶 `R` = 12 / 3 个 4-循环；3 阶 `R` = 21 / 5 个 4-循环 + 1 不动点；4 阶 `R` = 32 / 8 个 4-循环；4 阶 `Rw` = 48。
- 变异方向已验证：把层号换算的 `N - l` 改成 `l - 1`，T-06 与 T-09 会红。

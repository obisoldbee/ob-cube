## 9. 结果展示（补全原文缺失章节）

### 9.1 结果面板结构（右栏，进入任一 `ended_*` 终态后）

自上而下五个区块：

| 区块 | 内容 | v2.0 交付状态 |
|---|---|---|
| **结论区** | 一行大字结论，按终态取值：`已还原`（`ended_solved`）/ `超时`（`ended_timeout`）/ `步数耗尽`（`ended_move_limit`）/ `已放弃`（`ended_abandoned`）/ `提交无效`（`ended_invalid`）/ `未完成（页面关闭）`（`ended_interrupted`）。紧跟一行副文案说明触发原因（如"第 120 步仍未还原，步数上限 120"）。**内部错误不设第 7 个结论**，由 `ended_reason` 承载（v2.0 裁定，见 [`04-scoring-judging.md`](04-scoring-judging.md) §7.3） | 已交付 |
| **核心指标区** | 4 个指标卡：`总耗时（活跃）`、`总步数（HTM）`、`每秒步数`、`首次操作耗时`。发生暂停时，`总耗时` 旁显示 `暂停 M 秒` | **部分**：前三项已交付（`elapsed_ms` / `move_count` / `tps`）；`首次操作耗时`（`first_move_ms`）未落盘，P1。"比同题面上次快 12.4 秒"的对比参照依赖 F13，未实现 |
| **题面信息区** | 阶数、题目 ID、生成方式、seed 或题面指纹、蒙尘是否开启、观察模式、时间/步数限制、难度估计值 + 等级标签 | **部分**：`ChallengeRules` 已落盘全部字段；**难度标签 UI 未实现**（`difficultyLabel` 恒 `null`，F17 为 P1） |
| **运行信息区** | 参与者类型（人类 / Agent）、Agent 名称与版本、提示词版本（可选填写）、运行开始时间 | 已交付（`agent_meta` 由配置页手填，随记录落盘；v1.10 #Q8 裁定不为此新增第 10 个 API 方法） |
| **操作区** | 主按钮：`回放过程`、`同题面重跑`、`再挑战一次`；次按钮：`复制题面指纹`、`复制结果摘要` | 已交付（含 F12，v1.10 定为 P1 但实际已实现） |

**操作区行为定义**：`再挑战一次` = 保留当前配置生成**新题面**，回到 `ready`，不自动开始；`同题面重跑` = 同一题面重置状态/计时/计步/日志，回到 `ready`，不自动开始；两者都终止进行中的回放并清掉结果面板。**计时起点必须由玩家显式按下"开始挑战"**（v1.9 #43）。**MVP 不提供导出 JSON**（v1.9 #44）；`复制结果摘要` 只复制纯文本指标，不产生文件。

> **v2.0 字段名修正**：v1.10 写的"生成方式（`random_moves` / `preset`）"对应两个不同的代码字段，不要混用——
> - UI 配置层：`ChallengeConfig.puzzleSource` = `'random' | 'seed' | 'preset'`
> - 记录落盘层：`ChallengeRules.scramble_method` = `'random_moves' | 'seeded_moves'`（字面真源 `contracts.ts`）
>
> v1.10 的 `gen_mode` 这个字段名**在代码里不存在**；`preset` 也不是 `scramble_method` 的取值（预设题走 `preset_id` + `seeded_moves`）。v2.0 以 `contracts.ts` 为准，详见 [`08-data-model.md`](08-data-model.md) §13.1。

## 10. 过程回放

> **v2.0 把回放拆成两级。** v1.10 把"操作记录 + 逐帧回放"作为一个 P0 单项（F09），但实现只交付了其中一部分，同时项目 memory 又把回放记为 P1，形成 PRD/memory 双轨。v2.0 按能力边界切开：
>
> | 编号 | 能力 | 优先级 | 交付状态 | 相关 AC |
> |---|---|---|---|---|
> | **F09a** | 事件流完整记录 + **结果页原地重放** | **P0** | **已交付** | AC-46、AC-78（v2.0 新增） |
> | **F09b** | **独立回放页**：进度条拖拽 / 调速 / 单步 / 三视角 / 旧引擎版本提示 | **P1** | 未实现 | AC-47、AC-48、AC-50（均已标注 `[已降级至 P1]`） |
>
> 拆分理由与代价见 [`01-product-scope.md`](01-product-scope.md) §3.3。下面 §10.1 属 F09a，§10.2 / §10.3 属 F09b，§10.4 两级共用。

### 10.1 回放的数据基础（F09a，已交付）

回放不重跑逻辑，只重放事件流。每个运行记录保存：

- **题面重建信息**（不保存状态快照）：`seed` + `scramble` + `gen_version` + `notation_version`（`ss-2`）+ `initial_fingerprint`。载入时重放打乱得到初始状态，再用指纹校验一致；不一致抛 `E_REPRODUCTION_MISMATCH`；
- 事件流（有序数组，单一 `RunEvent` 类型 + `type` 七值：`move` / `view` / `start` / `pause` / `resume` / `submit` / `end`；每条 move 事件含指令、层集合、层数、转角、轴、时间戳、操作前后两个指纹、输入通道、归并来源）；
- 观察事件（`observation_id`、观察模式、返回的面集合——**不保存完整颜色数据**，需要时由回放引擎从初始状态顺序重放事件重建）。

**F09a 的已交付行为**（AC-78）：结果页/中栏按事件流原地重放，从**已还原态**起播、按 `MoveEvent` 顺序逐步施加，每一步用**回放态**为该步上色（不是用当前实时状态），重放不修改任何原始记录，"重置"同时复位相机并停止回放。当前实现是 260ms 定时器驱动。

### 10.2 回放界面（F09b，P1，未实现）

| 控件 | 行为 |
|---|---|
| 播放 / 暂停 | 按事件时间戳等比压缩播放（默认把总时长压到 20–40 秒，可调速度 0.5× / 1× / 2× / 4×） |
| 上一步 / 下一步 | 单步前进/后退，每步执行一次逆操作或正操作（AC-47） |
| 进度条 | 可拖拽跳转到任意步；跳转通过从最近关键帧快进实现，300ms 内定位（AC-48） |
| 时间轴刻度 | 显示每步的时间戳与累计步数 |
| 视角 | 回放期间可自由拖拽视角；**回放中的视角操作不写入原始记录**（只影响当前视图）。原始运行中的视角变化已作为 `type:'view'` 事件单独记录，不进入 move 事件流 |
| 操作日志联动 | 当前步在日志中高亮滚动到可视区 |
| 显示开关 | `显示步数`、`显示时间`、`显示观察发生点`（观察点用竖线标在时间轴上） |

UI 规格见 [`../execution/ui-shell.md`](../execution/ui-shell.md) §11（布局复用三栏 `mode = "replay"`、播放控制条替换转动矩阵、`height: 56px`）。

### 10.3 回放的三种视角模式（F09b，P1，未实现）

| 模式 | 说明 |
|---|---|
| **上帝视角** | 全开颜色，看完整过程。默认 |
| **观察者视角** | 按该次运行的 `observation_mode` 重现"Agent 当时能看到什么"。这是回放最有价值的模式——能直观看出"Agent 在单面观察下做了多少盲猜"。**注意：它依赖 F14 观察模式，而 F14 在 v2.0 也降为 P1**，因此这个模式的价值要等 F14 的配置入口落地后才能被用户真正触及 |
| **校验视角** | 每步显示操作前后 6 面颜色矩阵的差异高亮，用于人工核验引擎正确性 |

### 10.4 回放的边界（两级共用）

- 回放不修改任何原始记录；在回放中做操作只影响视图，不产生新事件。
- 若记录的 `engine_version` 与当前不一致，回放前提示"本次运行由旧版引擎生成，回放结果可能与当时不完全一致"，并提供"仍要回放"确认。不静默播放（AC-50，**P1**）。当前引擎版本字面真源是 `contracts.ts` 的 `ENGINE_VERSION = 'ob-cube 0.1.0'`——**UIUX 里写的"引擎 v1.0.0"已作废**，结果页读 `view.engineVersion`，不再硬编码。
- 单次运行事件数上限：默认 2000 条（全部 `type` 合计；2 阶/3 阶远超需求，4 阶也够）。超过时只保存前 2000 条 + 最终状态，并标注"记录已截断"；截断时 `view` 事件优先丢弃，`move` 与 `pause`/`resume`/`submit`/`end` 优先保留。**当前未验证**（无对应测试）。

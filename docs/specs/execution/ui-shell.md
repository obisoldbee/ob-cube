## 4 · 中栏操作区布局（本项目最难的设计点）

### 4.1 约束清点

必须在中栏同时容纳：

| 类别 | 动作数 | 说明 |
|---|---:|---|
| 6 个外层 × (顺时针 / 180° / 逆时针) | 18 | 全阶数 |
| 3 个中层 M / E / S × 3 变体 | 9 | 仅 3×3 |
| 宽转 `Rw Uw Fw Lw Dw Bw` × 3 变体 | 18 | 3×3（2 层）与 4×4（2 或 3 层） |
| 4×4 内层：近侧族 `2R 2U 2F`（9）+ 对面族 `2L 2D 2B`（9） | 18（拆 G5 / G6 两个 tab） | 仅 4×4 |
| 视角旋转 4 向 + 复位 | 5 | 不计步 |
| 打乱 / 重置 | 2 | — |
| 开始 / 暂停 / 继续 / 结束 | 4 | — |

合计 **62 个控件**。如果全部常驻，任何屏幕都会崩。

> **v2.0 修订：本表按代码 `src/ob-cube/src/ui/turn-matrix-data.ts` 的 `TABS_BY_SIZE` 追认重写。** 原设计稿有三处与实现不符：
>
> 1. **原表把「视角」列为 2 阶的一个 tab**（"仅 2 阶作为 tab"）——**实现里视角从来不是 tab**，它在舞台区 HUD，三个阶数一致。这条错记还传染到了 PRD v1.10 §3.4（把 2 阶第 2 组写成"视角"），已在 [`../prd/01-product-scope.md`](../prd/01-product-scope.md) §3.4 一并修正。
> 2. **原表把单内层拆成 G5「内层 近侧」与 G6「内层 对面」两个独立 tab**——实现是**一个 `内层` tab（10 控件）+ 近本侧/近对面位置切换**（`buildMatrixSpec(tab, size, innerPosition: 2|3)`）。组数仍是 5，AC-40 覆盖性不受影响，且比开两个 tab 更省同屏控件。
> 3. **原表完全没有「自由层」tab**——但实现里 2 阶（6 控件）与 4 阶（8 控件）各有一组。设计侧曾在附 C#6 裁定"删除自由层 tab，改『轴 + 起层 + 止层』选择器"，**该裁定从未执行，v2.0 正式作废**（理由见 [`UIUX.md`](UIUX.md) 的 v2.0 修订说明 #1）。自由层的实际形态是「轴 + 层槽任意多选」：`canSelectLayer` 只限层数上限、不强制连续，**非连续组合（如 4 阶同时选第 1、3 层）由"将提交"预览串显示 `—` 拦截**，因为记法无法序列化非连续区间。已立为 **AC-80**。
>
> 三个阶数的 tab 组数仍是 **2 / 3 / 5**（与原锁定一致），峰值同屏控件数 **19**（18 按钮 + 1 层选择器）未变。

> **前缀键共 4 个：`1` / `2` / `3` / `Z`。物理键共 11 个**（6 面键 + 4 前缀 + `Shift`）；`双击` 是手势不是物理键；`C` 前缀已撤回（§4.5F）。

**除 tab 之外的常驻控件**

| 优先级 | 分组 | 控件数 | 位置 | 出现条件 |
|---|---|---:|---|---|
| **P0** | **层选择器**（1 个控件，展开后含 1..N−1 层槽 + 3 个转向键） | **1** | 操作区头第二行左侧 | 全部阶数，常驻 |
| P0 | 视角 HUD：轨道 4 向 + `Home` + 面视 6 | 11 | 画布右上角悬浮块 | 3/4 阶常驻；**2 阶隐藏**（并入 `视角` tab） |
| P0 | 打乱 / 重置 | 2 | 画布左上角悬浮块 | 全部阶数 |
| P0 | 开始 / 暂停·继续 / 结束 / 放弃 | 4 | 左栏底部会话控制区 | 全部阶数；**Agent 模式不渲染「暂停」**（AC-58） |
| P0 | 常驻键位图（可折叠） | 1 面板 | 画布右下角 | 全部阶数，默认展开（PRD §5.5） |

**关键决策五条**：

1. **互斥 tab 保证同屏转动按钮恒 ≤18。** 三阶数峰值一致（均 19 = 18 按钮 + 1 层选择器），所以 G4 / G6 **没有折叠理由**——折叠反而延长 AC-40 要求验证的「可点击路径」，是负优化（PRD §5.6 原话）。
2. **层选择器是 AC-40 的正式完备机制，tabs 只是人体工学快捷方式。** 表述方式是**陈述句，不是算式**：「对任意 `(轴, 连续层区间, 转向)`，界面上都存在一条可点击路径（层选择器选区间 + 点该轴的转向键）」。所以 **G1 + 层选择器单独就能满足 AC-40**；G3/G4/G5/G6 是让高频动作少按一次按钮的预设，不承担完备性。
   > **不要写总数。** 我先前写过「4 阶 126 个三元组」是错的——4 阶的连续真子区间是 **9 个**（4 单层 + 3 双层 + 2 三层），不是 7 个；面口径 = `6 × 9 × 3 = 162`，轴口径去重后 81。一个算错的等式进了验收文档，Phase 4 会有人拿它生成用例。验收时让 QA **程序枚举**，不要手写总数。
3. **视角控制与打乱/重置移出按钮矩阵，做成画布上的悬浮 HUD。** 它们不是「转动」，混进矩阵会让用户把「转视角」当成「转魔方」，而这两件事一个计步一个不计步（PRD §7.1）。物理位置必须区分语义。
4. **会话控制放左栏，不放中栏。** 它们是「挑战」级操作，不是「魔方」级操作。
5. **2 阶隐藏视角 HUD，改在 `视角` tab 内给 11 个同尺寸按钮。** 理由：2 阶的 G1 tab 只有 18 键，矩阵区会空出约 1/3；把这部分空间还给视角（6 个面视键从 44×26 放大到 56×36），既解释了「2 阶 2 组」这个锁定，又不产生 HUD 与 tab 双份控件。

`--z-stage-hud: 10` 保证 HUD 在 canvas 之上但在浮层之下。HUD 用 `--btn-ghost-*`：透明底 + hover 出 `--bg-card`，避免在深舞台上出现一堆实心块。

**操作区头从 44px 加到 64px 的账**：1280×720 是 PRD 的最小支持窗口。64 + 420（舞台最小）+ 168（矩阵）= 652 < 720，可用。第 2 行专供「层选择器 + 状态栏」——这两个是 4 阶按键复用不产生歧义的第 1、第 2 道保障（PRD §5.3.2 保障 1/2），不能塞进 popover 或靠 hover 才出现。

**视角块的两个子区（不可合并）**：

> **硬约束（PRD §5.3.4 + AC-66~68）**：整体旋转只转相机，`applyMove` 对 `x`/`y`/`z` 一律返回 `E_NOTATION_ORIENTATION_NOT_MOVABLE`。因此**视角区不得出现任何 `x` / `y` / `z` 标签或角标**，也**不提供「绕 X 轴转」这类按钮**。视角控件只有 4 类：拖拽、`←→↑↓`、`Home`、6 个文字面视角按钮。
> 若用户/Agent 触发该错误（例如手输记法 `x`），状态栏 1500ms 显示：`整体旋转不是转动，不计步。请用视角控制。`——用 `--fg-3`，不用 danger 色：这是「你用了另一个功能」，不是出错。
- **轨道键**（`←` `↑` `↓` `→` `⌂`）：90° 步进旋转 + `Home` 复位。SVG 图标，十字排布，每键 32×32。
- **面视 6 键**（`上视 U` `下视 D` `左视 L` `右视 R` `前视 F` `后视 B`，2 列 × 3 行，每键 44×26）：必须带中文文字标签（PRD §11 可访问性 P1「面视角按钮带文字标签」），字母作左侧主标签、中文作副标签。

**蒙尘 / 暂停态下的 HUD 处理**：全部 HUD 保持可见。`ready` 态点击被 `NOT_STARTED` 拒绝时，只在状态栏显示 `挑战未开始` 1500ms，不弹错误；`paused` 态点击被 `PAUSED` 拒绝时，显示 `挑战已暂停`（完整文案见 §7.7）。

### 4.4 面卡排布规则（所有 tab 共用）

**核心规则：相对面成对，且「默认视角可见的三面」永远排在前，「不可见的三面」排在后。**

这不是随手排的。它同时在回答三个问题：
- 「我要转的那个面在哪」→ 与空间方位一致
- 「哪个面我看不见」→ 第二列/行就是，和蒙尘、三面观察模式的心理模型同构
- 「我按错了会怎样」→ 错误方向是「列」级的，不是「随机某个键」

### 4.5 各 tab 的按钮矩阵（文字线框图）

> 命名规则：面卡标题 = 「中文方位 + 面字母」；按钮标签 = 该按钮**实际会提交的 Singmaster 字符串**（不写键盘字符，键盘字符只在角标与键位图里）。

#### A. G1 `单层`（2×2 / 3×3 / 4×4，18 键）

**布局 L3：3 列 × 2 行**，用于 ≥1280px。

```
┌ 上层 U ─────────────┐ ┌ 右层 R ─────────────┐ ┌ 前层 F ─────────────┐
│ [U]    [U2]    [U'] │ │ [R]    [R2]    [R'] │ │ [F]    [F2]    [F'] │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
        ← 第一行 = 默认视角可见的三面（上、右、前）→
┌ 下层 D ─────────────┐ ┌ 左层 L ─────────────┐ ┌ 后层 B ─────────────┐
│ [D]    [D2]    [D'] │ │ [L]    [L2]    [L'] │ │ [B]    [B2]    [B'] │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
        ← 第二行 = 默认视角不可见的三面（下、左、后）→
```

**布局 L2：2 列 × 3 行**，用于 1024–1280px（尽力档）与 <1024px（兜底档）。

```
┌ 上层 U ─────────────┐   ┌ 下层 D ─────────────┐
│ [U]    [U2]    [U'] │   │ [D]    [D2]    [D'] │
└─────────────────────┘   └─────────────────────┘
┌ 右层 R ─────────────┐   ┌ 左层 L ─────────────┐
│ [R]    [R2]    [R'] │   │ [L]    [L2]    [L'] │
└─────────────────────┘   └─────────────────────┘
┌ 前层 F ─────────────┐   ┌ 后层 B ─────────────┐
│ [F]    [F2]    [F'] │   │ [B]    [B2]    [B'] │
└─────────────────────┘   └─────────────────────┘
```

> L3 的列顺序（U / R / F 与 D / L / B）让 U 与 D、R 与 L、F 与 B **上下对齐**。三组相对面各占一列，视线上下移动就是一对面——这是把 6 组降维成 3 对的关键。

#### B. G2 `中层`（仅 3×3，9 键，3 列 × 1 行）

```
┌ M 中层 ─────────────┐ ┌ E 赤道 ─────────────┐ ┌ S 站立 ─────────────┐
│ [M]    [M2]    [M'] │ │ [E]    [E2]    [E'] │ │ [S]    [S2]    [S'] │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
   R 与 L 之间的竖层        U 与 D 之间的横层        F 与 B 之间的深层
```

中文副标题按标准定义写：M = Middle（R/L 之间，顺 M 方向同 L）、E = Equator（U/D 之间，同 D）、S = Standing（F/B 之间，同 F）。这三个方向约定容易记反，所以在面卡标题上直接给中文方位，不靠用户背。

> 按钮标签是 `M` 而不是 `2L`：因为 PRD §5.6 的键盘表达是 `Z`+`A`=`2L`(=`M`)，而**引擎与日志的规范名**是 `M`（架构 §7 把 `M`/`E`/`S` 列为一等记法）。所以标签用 `M`，角标用 `Z·A`，状态栏同时显示 `Z A → 2L（M）`。三个地方三个用途，各自正确。

与 G1 同构，标签加 `w`：

└─────────────────────┘   └─────────────────────┘

```

**宽度警告（实现必读）**：`3Rw'` 是 **5 字符**，是全部标签里最宽的。当前按钮 `--btn-turn-w: 56px` 在 `--font-mono` 14px 下容不下 5 字符 + 角标。处理：**G4 / G6 两个 tab 激活时按钮宽度自动扩到 64px**（矩阵容器 `min-width` 允许），或者 `--text-base` 降到 `--text-sm`。二选一，我倾向**扩宽**，因为 5 字符缩到 12px 会与 3 字符标签的 14px 产生字号不一致。3 列 × 64 = 192px + 面卡内边距，中栏宽 ≥ 620px 即可容纳，满足 1280 最小窗口。

#### E. G5 `内层 近侧`（仅 4×4，9 键，3 列 × 1 行）

**标签族 = `2R` / `2U` / `2F`**（层 2，靠近 R / U / F 侧）。键盘入口 `Z` + **本侧**面键。

```
┌ 近 R 侧 ────────────┐ ┌ 近 U 侧 ────────────┐ ┌ 近 F 侧 ────────────┐
│ [2R]   [2R2]  [2R'] │ │ [2U]   [2U2]  [2U'] │ │ [2F]   [2F2]  [2F'] │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
  角标 Z D              角标 Z W              角标 Z S
```

#### F. G6 `内层 对面侧`（仅 4×4，9 键）— **与 G5 不是同一族**

**标签族 = `2L` / `2D` / `2B`**（层 3，靠近 L / D / B 侧）。键盘入口 `Z` + **对面**面键。

```
┌ 近 L 侧 ────────────┐ ┌ 近 D 侧 ────────────┐ ┌ 近 B 侧 ────────────┐
│ [2L]   [2L2]  [2L'] │ │ [2D]   [2D2]  [2D'] │ │ [2B]   [2B2]  [2B'] │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘

> **命名规则（PRD §5.7 + 架构 §7，唯一）**：每条轴上的层区间，**用离它更近的那个外层字母命名**；只有两端都不含外层时（纯中间层）才用区间记法。
>
> **✅ v2.0 已统一（原"一处尚未统一"的悬案已结）**：纯中间两层 `{2,3}` 的写法，曾是「PM §5.7 记为 `2-3R`，架构 §7 记为 `2-3Rw`」的两方分歧。**现行口径：`2-3R`（无 `w`）**，属 `ss-2` 记法版本；`2-3Rw` 仅作别名解析，归一化后不输出。裁定见 [`notation.md`](notation.md) 的 v2.0 修订说明与 [`../prd/03-notation-keyboard.md`](../prd/03-notation-keyboard.md) §5.7。
>
> 本文档当初的处置**依然正确且继续有效**：所有展示位（按钮标签、日志指令列、状态栏预览、角标）都取 `describeMove()` / `canonicalNotation` 的返回值，**不硬编码这个字符串**——所以这次改口径对 UI 层零影响，只影响引擎实现者。这正是"记法唯一真源"约束的价值实证。
> 所以 4 阶 R 轴的四层是 `R` / `2R` / `2L` / `L`，**没有 `3R` 这个记法**。G5 与 G6 是同一套 `Z` 前缀加不同侧的面键，**不是 `2R` 族与 `3R` 族**。
>
> **`C` 前缀不存在**（v1.3 撤回）。两个内层全部由 `Z` + 六个面键覆盖，`C`+面键既违反命名规则又与 `Z`+对面键重复。因此**物理键共 11 个**：6 面键 + `1` `2` `3` `Z` + `Shift`（`双击` 是手势不是物理键）。
>
> **为什么 G5 / G6 仍要拆成两个 tab 而不是合成一个 18 键的 tab**：因为它们的**键盘入口分属不同的面键**（本侧 vs 对面），而 tab 是「键盘分组的视觉镜像」。合成一个 tab 会让「这 9 个按钮按本侧键、那 9 个按对面键」变成需要在同一屏里记住两套规则——正是分组要避免的事。

#### G. `视角`（仅 2×2 作为 tab，11 键）

2 阶隐藏视角 HUD（§4.2 决策 5），把这些控件以更大尺寸放进 tab：

```
┌ 面视（6）────────────────────┐   ┌ 轨道（5）──┐
│ [上视 U] [右视 R] [前视 F]   │   │  [ ↑ ]     │
│ [下视 D] [左视 L] [后视 B]   │   │ [←][⌂][→]  │
└──────────────────────────────┘   │  [ ↓ ]     │
  每键 56×36（比 HUD 的 44×26 大） └────────────┘
```

#### H. 层选择器（1 个控件，全部阶数，AC-40 的正式完备机制）

```
折叠态（常驻在操作区头第二行左侧）：
  ┌ 层 1 ▾ ┐            ← 一个按钮，显示当前层区间的紧凑写法
  └────────┘

展开态（popover，--z-popover，宽 260px）：
  ┌────────────────────────────────────┐
  │ 轴    [ R | U | F | L | D | B ]     │  ← 6 选 1
  │ 起层  [ 1 | 2 | 3 | 4 ]             │  ← 4 选 1
  │ 止层  [ 1 | 2 | 3 | 4 ]             │  ← 4 选 1，必须 ≥ 起层
  │                                     │
  │ 预览：2-3R                          │  ← 由 describeMove() 返回，UI 不拼
  │ ──────────────────────────────      │
  │ [ ↻ 顺时针 ] [ ↺ 逆时针 ] [ 180° ]  │  ← 3 个转向键
  └────────────────────────────────────┘
```

| 决策 | 理由 |
|---|---|
| **只占 1 个控件位** | PRD §5.6 的峰值核算就是「18 + 1 层选择器 = 19」。所以它必须折叠成 1 个按钮，展开后才是层槽。这是硬约束，不是我的偏好 |
| **它与 tab 双向联动** | 选中 G1 tab → 层集合自动设为 `{1}`；G3 → `{1,2}`；G4 → `{1,2,3}`；G5 → `{2}`；G6 → `{3}`。反过来手动勾选层槽 → tab 变「无选中」态（全部 tab 取消高亮）。**同一状态只有一个真源**，避免「tab 说 A、选择器说 B」 |
| **4 阶的 9 个区间必须全部可选**（不是 7 个） | 完整枚举：`[1-1] [1-2] [1-3] [2-2] [2-3] [2-4] [3-3] [3-4] [4-4]`。其中 **`[1-3]`（=`3Rw`）与 `[2-4]`（=`3Lw`）是最容易被漏掉的两个**——它们恰好就是 G4 `宽转3` tab 的 18 个按钮。若层选择器表达不了这两组，**AC-40 为 G4 指定的验证路径就断了**。要求：起点可选 1..N、终点可选 1..N，且允许 `终点 − 起点 = 2`。各阶区间数：**2 阶 2 / 3 阶 5 / 4 阶 9** |
| **tab ↔ 选择器必须双向一致** | 点 G4 的 `3Rw` 按钮后，层选择器必须显示 `层 1-3`；点 G6 的 `2L` 之后显示 `层 2-4`（按该轴从 R 数）。**禁止出现「点了 `3Rw` 但选择器显示 `层 1`」的错位**——那说明 tab 与「唯一真源 `layerSet`」脱钩了，用户会以为自己在转单层 |
| **预览字符串不得美化**（AC-71） | AC-71 要求 `parse(describeMove(axis, L, t)) === (axis, L, t)`，即**预览显示的字符串必须能原样粘回引擎并解析成同一个动作**。所以：**不加空格、不改大小写、不把 `2-3R` 显示成 `2~3R` 或 `2–3R`（连字符不得换成 en/em dash）**。前缀 chip 与面键 chip 之间的 2px 空隙是**排版间隔**，不是字符串里的字符——复制出来的必须是连续的 `2-3R` |
| **「连续区间」而非任意勾选**（AC-40 已收窄） | PRD §5.7 把 AC-40 从「任意层子集」收窄为「**连续层区间**」，排除 `{1,3}` 这类既无记法也无用途的组合。所以层选择器是「起层 + 止层」两个 selector，**不需要支持任意勾选**——这一条省掉了多选 chip 的组合校验逻辑，也消掉了「勾了不相邻层怎么办」的歧义 |
| **全层被拦** | 起=1 且 止=N 即全层转动 → `E_MOVE_COVERS_ALL_LAYERS`。止层的第 N 项置灰不可选，旁边显示 `全层转动请用视角旋转`。**前置拦截，不让用户吃错误码** |
| **止层恒 ≥ 起层** | 改起层时若起 > 止，止自动跟到起；改止层时下限锁在起。不弹错、不重置整组 |
| **「预览」由引擎给字符串** | 选 `起2 止3` 到底该记 `2-3R` 还是别的，用户不必记规则。UI 不自行拼字符串（调用 `describeMove(axis, layerSet, amount)`），这也保证了预览与日志、API 三处字符串一致 |
| **3 个转向键作用于哪个面** | 作用于「当前面」。当前面的来源优先级：① 最后一次 hover/点击的面卡；② 默认 F。UI 上必须显示当前面（如 `作用于：R 面`），否则用户在 popover 里按了 `↻` 不知道转了哪个面 |

> **AC-40 的完备性论证（写法务必用陈述句）**：「层选择器可选任意 `(轴, 连续层区间)`，而 G1 的 18 个按钮是该区间在 6 个面上的 3 种转向执行器。因此对任意 `(轴, 连续区间, 转向)` 三元组，都存在一条 `层选择器选区间 → 点转向键` 的可点击路径。」**不写总数**——总数交给 QA 程序枚举（4 阶连续真子区间 9 个 × 6 面 × 3 转向，去重后以程序结果为准）。

### 4.6 为什么 4 阶有 5 组 tab 却不会显得过载

| 手段 | 效果 |
|---|---|
| 互斥 tab | 同屏转动按钮 **恒 ≤18**（G1 18 / G2 9 / G3 18 / G4 18 / G5 9 / G6 9），三阶数峰值一致（18 + 1 层选择器 = **19**），4 阶不比 3 阶挤 |
| 相对面成列 | 6 个面卡降维成 3 对，工作记忆只持有「上下 / 左右 / 前后」三对 |
| 标签用 Singmaster | `3Rw'` 最宽 5 字符。中文「右数第三层宽转逆时针」需要 10 个汉字，不可行 |
| 变体按钮不等宽 | 每卡内三键 `1fr / 0.8fr / 1fr`：180° 按钮视觉更窄（它是合成动作，认知权重低），同时避免「相同卡片网格」的反模式 |
| G4 / G6 按需扩宽 | 5 字符标签激活时按钮 56 → 64px，字号不变（**不靠缩字号解决**，否则两组 tab 的字号不一致） |
| 5 组 tab 的宽度 | 「单层 / 中层 / 宽转2 / 宽转3 / 内层2 / 内层3」各 2–3 字，5 个 tab 约 340px，中栏 ≥620px 时与右侧阶数徽章不冲突。4 阶最多 5 个（单层/宽转2/宽转3/内层2/内层3），3 阶 3 个，2 阶 2 个 |
| 视角/会话/打乱移出 | 矩阵只承担「转动」，不承担 13 个异质控件（轨道 5 + 面视 6 + 打乱 2） |
| kbd 角标只挂两种形态 | 按钮上只有 `W`（1ch）与 `⇧W`（≈2ch）；180° 按钮**不挂角标**；前缀型 `Z·W` 只在键位图与浮层。见 §5.1 |

### 4.7 转动按钮的样式规则

- 不做颜色编码。18 个键同色（`--btn-turn-bg`），因为**颜色编码会和魔方六色打架**，玩家最终靠位置记忆而不是颜色。
- 三种变体的区分靠**标签 + 宽度 + 位置**：`U`（宽）/ `U2`（窄）/ `U'`（宽）。
- 唯一的状态色用在 `:active`：`--btn-turn-bg-active`（accent 12%）+ `--btn-turn-fg-active`，80ms 起效。
- **180° 按钮的权重说明（本轮更新）**：PRD v1.2 已删除 `Alt` 备选通道，所以关闭「双击归并」后，**180° 按钮是该操作在键盘通道之外的唯一入口**。但**仍然不给它加颜色**——加色会让 18 个按钮出现第二个视重点，破坏「位置记忆」策略。提高权重的手段是：① 按钮宽度保持 `1fr`（视觉上不比顺/逆小）；② 悬停时正常联动层描边；③ 在键位图里用 `W×2` 明确标出键盘路径。**不加色，加的可达性与一致性。**
- `Space` / `Enter` / `Esc` 在矩阵内不触发任何转动（见 §5.6 禁用键表）。

### 4.8 选中层与悬停联动的统一规则（三个控件 ↔ 一个 3D）

面卡、转动按钮、层选择器（§4.5H）这三个控件都在描述「哪些层」，它们必须与 3D 场景共享同一个「当前指向的层集合」状态，否则用户永远在猜。**单一真源**：`layerSet`（一个整数集合）是唯一状态；tab 是高亮视图，层选择器是可编辑视图，矩阵按钮是「把 `layerSet` 应用到某个面」的执行器。规则如下：

| 触发源 | 3D 反馈 | 按钮/面卡反馈 | 持续时间 |
|---|---|---|---|
| **hover** 转动按钮 / 层选择器的层槽 | 该层集合的外轮廓描边，`--accent` 30% 透明，**不压暗邻层** | — | hover 期间 |
| **hover** 面卡标题 | 该面的 4 条边描边（只描边不填充），用来回答「哪个面是 F」 | 面卡边框 → `--border` | hover 期间 |
| **hover** 面卡整体 | 该面整体提亮 4% | 同上 | hover 期间 |
| **按下**（键盘或点击） | 描边升到 100%，启动 L3 邻层压暗（§5.3） | 按钮 `:active` | `--dur-turn` + 120ms 淡出 |
| **层选择器的层槽改变** | 新的层集合**持续**描边（100%），直到下一次转动或层集合再变 | 层槽 chip 勾选态；tab 取消高亮（进入「手动层」态） | 持续（这是状态，不是动效） |
| **前缀态存在**（按了 `2` 未按面键） | 对应层集合以**虚线**描边（区别于实线的「已选中」） | 状态栏（§5.4） | 前缀存活期内（≤3s） |

**为什么「虚线 vs 实线」要区分**：「按了前缀但还没按面键」和「已经选中这些层待转」是两种不同状态，前者随时可能被取消。用线型区分而不只是颜色深浅，是因为颜色深浅在深色舞台上不够明显。

**实现代价说明**：这套联动全部是「设置材质参数 + 增删一条 line 对象」，没有额外 draw call 增长（描边复用一个对象），也不需要后处理。这是本项目 ROI 最高的交互设计。

## 5 · 键盘映射的可视化

> **数据源**：[`../prd/03-notation-keyboard.md`](../prd/03-notation-keyboard.md) §5.6「键盘映射交付表」是本章的唯一数据源。本节不重复定义映射，只定义「用户怎么学会它、怎么知道自己按对了」。
> 已按 PRD v1.2 更新：`Alt` 备选通道已删除、`Enter` 在 `running` 态无绑定（提交只走按钮）、角标只有两种形态、归并动画禁止闪回帧。

### 5.0 需要被表达的 5 种输入形态

| 形态 | PRD 定义 | 举例 | 视觉载体 |
|---|---|---|---|
| 单键 | 一个面键 | `W` = `U` | **按钮角标** `W` |
| 单修饰 | `Shift` + 面键（同时按） | `⇧W` = `U'` | **按钮角标** `⇧W` |
| 双击 | 同面键 300ms 内两次（同一动作的重复） | `W W` = `U2` | **不挂角标**，只在键位图/浮层 |
| 前缀 | 层深前缀 + 面键（**先按后按，是状态**） | `Z`→`D` = `2R`；`Z`→`A` = `2L`；`2`→`D` = `Rw`；`3`→`D` = `3Rw` | **不挂按钮角标**，只在键位图/浮层写 `Z·D` / `Z·A` / `2·D` / `3·D` |
| 三段 | 前缀 + 修饰 + 面键 | `2`+`⇧`+`D` = `Rw'`；`Z`+`⇧`+`D` = `2R'`；`Z`+`⇧`+`A` = `2L'` | 只在键位图/浮层写 `2·⇧D` |

**为什么 G5 / G6 是唯一给前缀挂角标的两个 tab**：这两个 tab 的按钮标签是 `2R` / `2L`，而键盘是 `Z`+`D` / `Z`+`A`——**标签和键位长得完全不同**（`2R` 极易被误读成「按 2 再按 R」，实际是「按 Z 再按 D」）。不挂角标，用户只能自己猜「2R 是不是按 2 和 R」，猜错后行为完全不同。所以这两个 tab 必须挂，且必须标成 `Z D` 而不是 `2 R`。

**为什么其余前缀型与双击都不挂在按钮上（PRD §5.6 的建议，我采纳并补理由）**：
1. 18 个按钮里如果 6 个是 `W`、6 个是 `⇧W`、6 个是 `W×2`，角标宽度会是 1ch / 2ch / 3ch 三种，**列不对齐**，扫读价值崩溃。
2. 前缀型是「跨 tab 的」——G3 的按钮角标写什么？写 `2·D` 就把「先按 2」这个动作固化到了按钮上，用户会以为必须按 `2` 才能触发这个按钮，而实际上点按钮也直接生效。**角标只该描述「这个按钮额外提供了一条什么键盘捷径」，不描述前置状态。**
3. 结果：按钮角标只承担「6 个最常用动作的锚点」（PRD 原话「这是 60 秒学会的锚点」），其余全部交给键位图与浮层。**少即是多。**

### 5.1 角标的两种形态与实现规格

| 形态 | 结构 | 宽度 | 用在哪 |
|---|---|---|---|
| **单键** | 键帽 chip（实心 `--kbd-bg` + 1px `--kbd-border` + `--radius-sm`），`--text-xs`(11px) 等宽 | 1ch（约 20px 含内边距） | 6 个「顺时针」按钮（`U` `D` `L` `R` `F` `B`） |
| **单修饰** | 8px 的 `⇧` 符号（无底、`--fg-3`）**紧贴**右侧键帽 chip，间隔 `--kbd-mod-gap: 0` | ≈2ch（约 30px） | 6 个「逆时针」按钮（`U'` `D'` `L'` `R'` `F'` `B'`） |
| 无 | 不渲染 | — | **6 个 180° 按钮**、G2/G3/G4 全部按钮 |
| **双段（例外）** | 前缀 chip（空心）+ 面键 chip（实心），2px 间隔 | 3ch | **仅 G5 / G6 的 9 个按钮**：G5 标 `Z D` / `Z W` / `Z S`，G6 标 `Z A` / `Z X` / `Z Q` |

补充规格：
- `⇧` 用 8px 而不是 11px：**用更小的符号换更窄的角标**。这是把 `Shift+W` 压进 2ch 的唯一办法，PRD §5.6 已明确这个意图。
- 位置：按钮**右下角内侧 4px**（右上角留给「当前层已被选中」的指示点，见 §4.8）。
- `--kbd-key-fg` = `--fg-3`；hover 时提亮到 `--fg`。
- `--kbd-key-bg` 在按钮底色（`--btn-turn-bg` = `--bg-card`）上对比不足，必须用更暗的 `--bg-sunken` 形成「凹槽」感——这样角标读起来像「贴在按钮上的一张标签」，而不是第二个按钮。
- **宽度约束**：角标总宽 ≤ 按钮宽度的 **55%**（不是 70%，因为 2ch 加内边距在 56px 宽按钮上已接近临界）。`3Rw'` 这类 5 字符标签 + 无角标，所以 G4/G6 不冲突。

**显示策略**：

| 断点 | 角标行为 | 理由 |
|---|---|---|
| ≥1440px | 常显完整形态 | 学习型工具，角标是教学内容而非提示 |
| 1280–1440px | 常显 | 1–2ch 不构成挤压 |
| 1024–1280px | **hover / focus 时显示**（120ms 淡入），并在状态栏显示 `当前按键 ⇧D → R'` | 空间不足，转为按需 |
| <1024px | 不显示（PRD §4 已把移动端深度适配列为 Out-of-Scope） | — |

### 5.2 常驻键位图（P0，PRD §5.5 硬性要求）

PRD §5.5 把「常驻键位图」列为 P0，理由是键盘方案故意没用「字母=面名」而改用「展开图投影」，用户必须能不背。本设计做成**两级 + 一个一次性引导**：

**一级 · 常驻迷你键位图**（中栏舞台右下角，`--z-stage-hud`，**默认展开**）
- 200×150px，`--bg-card` 60% 不透明底 + `--elev-2`，`--radius-lg`。
- 内容 = PRD §5.2 那张「五个面在左手十字上的位置图」，不是表格：

```
        ┌───┐
        │ W │ U 上
   ┌────┼───┼────┬┈┈┈┐
   │ A  │ S │ D  ┊ Q ┊      ← Q 用虚线框：它是「看不见的那一面」，
   │ L  │ F │ R  ┊ B ┊        不属于 W A S D X 这个实线十字组
   └────┴───┴────┴┈┈┈┘
        │ X │ D 下
        └───┘

   ⇧ 反向   连按两下 = 180°   前缀 1 2 3 Z
```

- **`Q` 必须用虚线框 + 与十字团之间留 4px 空隙**（AC-69 的替代缓解：不改输入行为，只改「一眼看出它不属于同一组」）。这是图形键位图相对表格的唯一不可替代价值——表格无法表达「这个键在空间上不属于这一组」。

- **图形化而非表格化**，因为这是空间记忆。表格会毁掉它的作用（用户记的是「W 在 S 上面」，不是「U 对应 W」）。
- 可折叠为 32×32 的「键盘图标」按钮；折叠状态写入 `localStorage`。

**二级 · 完整快捷键浮层**（点迷你图右上角的展开图标，或按 `?`）
- `--z-popover`，锚定中栏右上，宽 460px。
- 四段：`转动量`（3 行）/ `层深前缀`（`2`/`3`/`Z`/`C` 四行 + 各阶可用性表）/ `视角与流程`（`←→↑↓` `Home` `Space` `Enter` `Esc` `F2`）/ `禁用键与原因`。
- 前缀段必须写**四例**：`Z·D`=`2R`（=M'）、`Z·A`=`2L`（=M）、`2·D`=`Rw`、`3·D`=`3Rw`，并标注哪几组只对 4 阶有效。**不得出现 `C·D`——`C` 前缀已撤回。**
- 每段末尾一句「为什么这样设计」，把 PRD §5.2 的取舍搬上来。**用户不理解取舍就会自己改键位，而 MVP 不做自定义键位。**
- 收起：`Esc`、点击外部、再按 `?`。

**三级 · 首次引导（一次性，PRD §5.5）**
- 触发：首次进入 `running` 态。
- 形态：魔方正上方一条半透明提示条（`--bg-float` 90%，`--elev-2`），一行文案：
  `按 W A S D X Q 转面 · ⇧ 反向 · 连按两下转 180°`
  第二行小字：`完整键位图在右下角，按 ? 打开`
- 消失条件：**用户首个有效操作后**立即消失（不是计时消失）；写入 `localStorage` 的 `guide_seen`，**永不重复**。
- 不阻塞操作：提示条不接收指针事件（`pointer-events: none`），下方按钮照常可点。

> `?`（`Shift + /`）与 PRD 禁用的裸 `/` 不冲突：Firefox 快速查找由 `/` 单独触发，`Shift + /` 不触发。但必须 `preventDefault()` 并做兜底——若 `?` 未捕获，界面按钮是唯一保证路径，**不能只依赖 `?`**。

### 5.3 按键反馈：三层跨模态高亮（**唯一不能砍的交互**）

**问题**：3D 视角旋转后，「R 面」和屏幕方向脱钩。默认视角下 R 面在屏幕右侧；转到背面后 R 面就变成屏幕左侧甚至斜向。此时用户按下 `D` 键（PRD 把 `D` 键映射给 R 面），看到某条斜边在转，**既无法确认转的是哪一层，也无法从键位推断**（键位只编码「哪个面」，不编码「哪一层」）。4 阶有 4 层。**这是最容易翻车的地方**（§0 结论 10）。

**方案：三层同时发生，让「按键 → 层」的映射无需推理。**

| 层 | 视觉 | 时长 | 目的 |
|---|---|---|---|
| **L0 · 按下回显** | 该按钮 `:active` 背景 → `--btn-turn-bg-active`（accent 12%），文字 → `--accent`，`translateY(1px)` | 80ms 起，按住保持，**松开后保持高亮至 120ms** | PRD §5.5 要求的「按下即回显高亮 120ms」，确认「我按到了这个键」 |
| **L1 · 该层轮廓描边（核心）** | 3D 中被转动的**一整层**（含宽转的 2/3 层）外轮廓画 2px `--accent` 描边 | `--dur-turn` 期间保持，结束后 120ms 淡出 | 确认「转的是这一层」，不依赖视角方向 |
| **L2 · 邻层压暗** | 与该层相邻的两层贴纸整体压暗 4% | 同 L1 | 让「动了的那层」从整体里跳出来 |

**L1 的实现要点**（写进 Spec）：
- 描边是**物理板块的轮廓**，不是贴纸轮廓。3×3 转 R 时，是 9 个 cubie 组成的 3×3×1 板块的 12 条棱，不是 9 张方贴纸各自的边框。
- 屏幕空间恒定 2px（`LineMaterial` 的 `linewidth` + `resolution`），不随缩放变化。
- 复用**一个** `Line` 对象（几何随层集合重建，对象不重建），draw call 上限 +1。
- hover 预高亮 = 同一对象把 alpha 改成 0.30，**不新增对象**。
- `prefers-reduced-motion` 下描边保留（它是状态指示不是动效），只是没有淡出过渡。
- **描边颜色是 `--accent`**——这是 §2.4「3D 舞台区禁 accent」规则的**唯一例外**，因为它是覆盖在贴纸上的线，必须与六色全部冲突才看得见，且生命周期只有 `--dur-turn`。评审时显式放行，不允许扩展到其他元素。

### 5.4 状态栏：前缀态与归并的可见化（PRD §5.3.2 保障 1/2 的承载）

位置：操作区头第二行右侧，`--font-mono`，`--text-sm`，单行不换行（超出省略，`title` 给全文）。

| 状态 | 状态栏显示 | 视觉 |
|---|---|---|
| 无待生效输入 | `就绪` | `--fg-3` |
| 按了前缀 `2` | `层深 2 层 → 将提交 Rw` | 前缀 chip 点亮；预览指令 `--fg` |
| 按了前缀 `3` | `层深 3 层 → 将提交 3Rw` | 同上 |
| 按了前缀 `Z` | `内层第 1 层 → 将提交 2R` | 同上 |
| 按了前缀 `Z`（且已 hover/选中对面面卡） | `内层·对面侧 → 将提交 2L` | 同上 |
| 按了 `Shift`（未按面键） | `反向 → 等待面键` | `⇧` 符号点亮 |
| **前缀 + `Shift` 都按下** | `层深 2 层 · 反向 → 将提交 Rw'` | **这是 PRD §5.3.2 明确点名的场景，必须给完整预览** |
| 前缀 3 秒未消费 | 淡出回 `就绪`，同时一行 1200ms 的 `层深已取消`（`--fg-3`） | `--dur-slow` 淡出（**这就是 PRD 要求的「取消时淡出提示」**） |
| 双击归并发生 | `已合并为 R2` | 1200ms 后回 `就绪`，`--accent` 文字 |
| `paused` 态任意操作 | `挑战已暂停。计时已冻结。` | `--warn` |
| `ready` 态任意操作 | `挑战未开始` | `--fg-3` |
| 层选择器手动改了区间 | `手动层 2–3 → 将提交 2-3R` | `--fg`，并显示「作用于：R 面」 |

**为什么必须给「将提交」完整预览而不是只显示前缀**：前缀可组合（`2`+`⇧`+`D` = `Rw'`），只显示「层深 2」用户还得自己推。显示完整指令，用户按下之前就知道结果——这才是 PRD 说的「不需要记忆」。

**为什么状态栏不能做成 toast**：它是持续显示的当前状态，不是一次性通知。toast 会消失，状态栏不会。

### 5.5 输入管道（三段式）与归并动画（禁止闪回帧）

PRD 的双击归并让「先进先出队列 + 连击计数」这个模型失效，且 v1.2 明确纠正了旧版「撤销再重放」的错误表述。正确模型：

```
① 前缀态 ──→ ② 面键判定 ──→ ③ 300ms 归并窗口 ──→ 定稿
                                    │
                                    └─ 窗口内同面键再按 → 3D 继续正向转到 180°
                                                           日志行标签就地变 R2
```

| 环节 | 规则 | UI 反馈 |
|---|---|---|
| ① 前缀态 | 按 `2`/`3`/`Z`/`C` 进入；只保留**一个**前缀（不接受 `2` 后按 `3`，后者替换前者）；3s 超时自动取消 | 状态栏（§5.4）+ 层选择器同步高亮 |
| ② 面键判定 | 有前缀 → 消费前缀；无前缀 → 单层；`Shift` 同时按 → 反向 | L1 层描边**立即**点亮，不等动画结束 |
| ③ 归并窗口 | 300ms 内**同面键、同修饰、同层深**再按 → 进入归并；有**任何其他输入插入**则窗口立即关闭，两次独立动作 | 状态栏 `已合并为 R2` |
| 快速连击（不同面键） | 进入渲染队列，按序执行，**不丢**。队列 ≥2 时状态栏显示 `执行中 2`（`--fg-3`），≥5 转 `--warn` | 队列计数 |
| `event.repeat === true` | 直接忽略（PRD §5.3.5），**且不进入归并窗口** | 无 |
| 非法组合（如 2 阶按 `2`） | 无转动；状态栏 1500ms 显示 `2 阶无宽转` | `--fg-3`，不用 danger 色——这是教学不是报错 |

#### 归并的动画规范（PRD v1.2 硬要求：单调推进，零回退帧）

**3D 动画**：

```
R  按下 → 0° ──90° 处提交并继续──→ 180°     单调推进，中间不停
```

- 第一次按下：动画从 `0°` 走向 `90°`。到 `90°` 时**不做「回 0° 再转 180°」**（那会产生抖动，是 PRD 明令禁止的闪回帧）。
- 第二次按下落在 300ms 窗口内：**动画从 `90°` 继续走向 `180°`**，一段连续运动。
- 归并期间 L1 层描边**保持点亮不中断**，并在第二击时亮度提升 20%（`--dur-fast`），让用户察觉「这两下被合成了一步」。
- 如果第二次按下时 `90°` 动画已结束（即 90°→ 静止 →180°）：从静止位继续转向 180°，**仍然不回退**。视觉上是「转一下、停一下、再转一下」，但角度单调递增。
- `prefers-reduced-motion`：直接跳到终态（`90°` 或 `180°`），无过渡。

**日志行（关键：不删行、不塌陷，避免闪回）**：

| 时刻 | 日志区表现 |
|---|---|
| 第一击 | **立即**在底部追加一行，进入「待定」态：`#042  R  ···  ›`（`--kbd-*` 一般的弱化：整行 `opacity: 0.55`，结果列显示一个 6px 的 `--fg-3` 圆点表示「待定」） |
| 第二击（窗口内） | 该行**就地变形**：移动列 `R` → `R2`（`--dur-fast` 交叉淡入，不改变行高），结果列圆点转为 `--success` 的对勾，`opacity` → 1，`title` 挂 `merged_from: R + R`。**行号不变**（净 1 步），**不新增行**，**不删除行** |
| 窗口超时未归并 | 该行 `opacity` 0.55 → 1，圆点转对勾，定稿为 `R`。**无任何位移动画** |

> **为什么不做「删掉旧行 + 插入新行」**：那会产生一次高度塌陷 + 高度展开（28px → 0 → 28px），在视觉上等价于「闪回」，且会把下方所有行整体上移再下移——正是 PRD v1.2 要禁止的东西。**「就地变形」是唯一正确的解法。**
> 同理，旧稿的「行高 0 收拢」动画**已删除**。日志行一旦出现，只允许改内容，不允许改行高。

### 5.6 禁用键与首次引导

**禁用键表（合并 PRD §5.3.5 与我占用的键）**

| 键 | 状态 | 原因 |
|---|---|---|
| 任何 `Ctrl` / `Cmd` 组合 | **禁用**，不注册不 `preventDefault` | 浏览器保留键，`Ctrl+W` 无法可靠拦截 |
| `Alt` + 任意 | **禁用**（PRD v1.2 已删除原来的 `Alt` 备选通道） | 会触发浏览器菜单栏聚焦。**180° 关闭双击归并后只剩界面按钮一途** |
| `Tab` | 禁用（可访问性通道） | 焦点切换 |
| `F1` `F5` `F11` `F12` | 禁用 | 系统/浏览器功能 |
| 裸 `/` | 禁用（Firefox 快速查找） | — |
| 长按重复（`event.repeat`） | 忽略 | 会连发导致误转 |
| `Space` | **仅 `ready` 态 = 开始挑战；`finished` 态 = 返回配置**；`running` / `solved_pending` / `paused` 无绑定（只 `preventDefault` 防滚动） | 避免还原中误触；暂停只走界面按钮（F18），`Space` 不参与暂停 |
| `Enter` | **`running` 态无绑定**（PRD v1.2 已改）。仅配置页「创建挑战」 | 误按 `Enter` 会产生一次 `NOT_SOLVED`，累计 3 次直接终止挑战。**提交只走按钮** |
| `Esc` | 关闭浮层 / 关闭「放弃确认层」（同一件事） | — |
| `?`（`Shift+/`） | 我占用：打开快捷键浮层 | `Shift+/` 不触发 Firefox 快速查找 |
| `←` `→` `↑` `↓` | 我占用：视角 90° 步进 | 需 `preventDefault()` 阻止页面滚动 |
| `Home` | 视角复位 | `preventDefault()` |
| `F2` | 记法输入框（P1 F16） | 不用 `/` |

**AC-69（PRD 新增，我采纳）**：任何面键输入**不得**被静默丢弃。归并窗口内到达不同面键时，**必须立即执行该面键对应的转动**，不得改写为其他指令。

**AC-70（配套）**：不得存在**仅作用于 keyboard 通道**的输入过滤。键盘、鼠标按钮、Agent `applyMove` 三条通道必须走同一套校验。

> 这条否决了我上一轮提的「`W` 后 120ms 内忽略 `Q`」防抖方案。PM 的否决理由比我原来的关切更硬，我认：① 被丢弃的输入会让**可见魔方与记录状态分叉**（用户看到 6 面、记录里 5 步），在评测平台上是正确性缺陷；② 只有人类会被过滤，Agent 的 `applyMove` 不过滤，**直接破坏人机同轨**。这两条任一条都比「手抖可能转错一面」严重。
>
> **替代方案（我做）**：在**图形键位图**里给 `Q` 加「背面」视觉标记——虚线框 + 一个极小的背面指示（`Q` 位于十字团外围的斜角位，用虚线把它与 `W A S D X` 的实线键区分开）。这不改变任何输入行为，只改变「一眼看出它不属于同一组」。**这正是「做图形不做表格」的价值：表格无法表达「这个键在空间上不属于这一组」，图形可以。**

**首次引导文案（一次性，PRD §5.5）** —— 见 §5.2 三级。

**「按下即回显」的兜底**：L0 的 120ms 高亮必须在**键盘与鼠标两个通道都生效**。鼠标点按钮时，按钮 `:active` 天然有，但**松开后要保持 120ms**（用 `:active` + 一个 120ms 的 class），否则快速点击时用户看不到反馈。

## 7 · 关键状态设计

### 7.1 计时器（`--timer-*`）

| 状态 | 触发 | 视觉 | 文案 |
|---|---|---|---|
| `idle` | 未开始 | `--timer-fg`，显示 `0.00`（或 `--:--`，见下） | 限时模式显示配置时长；不限时显示 `--:--`（表示无上限，不是无数据） |
| `running` | 进行中 | `--timer-fg`，整数 40px，小数 20px `--fg-2` | `12:34.56` |
| `warning` | 剩余 ≤60s | 数字 → `--timer-fg-warning`；计时器左侧出现 1px 高的倒计时条（宽度按剩余比例，颜色从 `--accent` 线性插值到 `--warn`） | 同上 |
| `critical` | 剩余 ≤10s | 数字 → `--timer-fg-critical`；倒计时条变 `--danger`；**每秒一次 200ms 的柔和不透明度呼吸（1.0 → 0.82 → 1.0），不闪烁** | `00:07.31` |
| `paused` | 用户暂停（仅人类模式） | **数字与倒计时条同时冻结**（`--timer-fg` 不变色），前方加一个 `--warn` 的静态小标签 `已暂停` | 停在暂停时刻的 `12:34.56`；恢复后从冻结点继续（AC-73） |
| `timeout` | 归零 | 停在 `00:00.00` + `--timer-fg-timeout`；中栏魔方整体加 `saturate(0.4)` 滤镜；画布顶部出现 2px `--danger` 实线 | `超时` |

**关键规则**：
- **不闪烁。** 闪烁是最容易被滥用的警示手段：① 3Hz 以上可能诱发光敏性反应；② 高频闪烁在长时段使用中造成疲劳；③ 它与「计时器正在跑」这个真实信号争夺注意力。用「降饱和度 + 柔和呼吸 + 进度条」三重表达紧迫感，信息量更大且不刺眼。
- 容器 `min-width: 7ch` + `tabular-nums` + 右对齐 → 数字变化时零跳位。
- `aria-live="off"`：计数器每 10ms 更新，绝不能进 live region。超时事件单独用 `aria-live="assertive"` 播报一次。
- **`paused` 态的计时器是本项目最容易被做错的地方**：3D 场景冻结在暂停前最后一帧（不渲染新动画），**倒计时数字与倒计时条也必须同时冻结**。PRD v1.9/v1.10 已把暂停改为“真暂停”：暂停期间 `elapsed_ms` 不增长、`remaining_ms` 不变（AC-73/74）。如果实现成“数字继续跳”，就是旧口径残留，会直接违反 PRD。
- `paused` 态数字**不变色**（不改 `--warn`）：因为变色会被读成「出问题了」，而暂停是用户主动的正常操作。遮罩与“计时已冻结”文案承担规则提示。

### 7.2 步数计数器

| 模式 | 视觉 | 警告 |
|---|---|---|
| 不限步 | `步数` 标签（`--text-sm`，`--fg-3`）+ 数字（`--text-xl`，`--font-mono`，`--fg`） | — |
| 限步 | 同左，但数字为 `68 / 120` 格式；下方一条 2px 耗尽条（`--bg-card` 底 + `--accent` 前景，按已用比例） | 剩余 ≤20% → 数字与条转 `--warn` |
| 耗尽 | 数字转 `--danger`，耗尽条全满，挑战结束 | 结果面板结论区显示 `步数耗尽` |

规则：**HTM 计步口径必须在标签上写出来**（`HTM` 三个字母，`--text-xs`，`0.08em` 字距，`--fg-3`）。因为 `R` / `R'` / `R2` 都算 1 步，与「转动角度」直觉不符，不标注一定会被质疑。

**口径固定，不做成可切换控件**（PRD §7.1 + PM 裁决）：

| 位置 | 口径 | 能否切换 |
|---|---|---|
| 挑战中实时步数 | 本平台 HTM | **不可切** |
| `move_limit` 限步判定 | 本平台 HTM | **不可切**（判定标准必须开始前锁定，否则同一 run 内可被口头重解释） |
| 结果面板主指标 | 本平台 HTM | 不可切 |
| 结果面板「其他口径」区 | `HTM-layer` / `QTM` | 可切，**只影响展示与对比表排序，不回写记录、不影响判定** |

所以挑战中的步数标签是一个**只读的静态角标**，不是控件。若做成下拉，会暗示「换个口径就能让步数变少」，这是对判定规则的破坏。

**实现前提（PRD §13.4，比「多层计 1 步」更底层）**：

> **`move_count` 必须由「事件数」派生，不得由转动层数之和派生，也不得由角度除以 90 派生。**

三种情况只有这一个算法能同时正确：
- **归并**：`R` + `R` → `R2` = **1 个事件**（不是 2 步）
- **宽转 / 内层**：`3Rw` = **1 个事件**（不是 3 步）
- **180°**：`R2` = **1 个事件**（不是 2 步）

如果实现成「层数之和」或「角度/90」，这三种情况会各自漂移，而它们恰好是 3 阶与 4 阶、人类与 Agent 出现频率最高的三类操作——**跨阶对比会从「有偏差」变成「无意义」**。这一步漏了，上面「多层计 1 步」的规则等于没写。

### 7.3 操作日志（`--log-*`）

**结构**：右侧栏中部，`role="log"`，`--log-bg` 底，行高固定 28px。

**每行格式**（等宽，列宽固定）：

```
#042   R'        12ms   OK
 │      │          │     └─ 结果：OK / 非法 / 超时
 │      │          └─────── 引擎执行耗时（--log-meta-fg，右对齐）
 │      └────────────────── 操作指令（--log-move-fg，**引擎规范族**，见下）
 └───────────────────────── 序号（--log-idx-fg，右对齐，4 位补零）
```

**指令列只用「引擎规范族」，不进别名**（PRD §5.7）：

| 阶数 | 日志列显示 | 状态栏额外显示 | 说明 |
|---|---|---|---|
| 3 阶中层 | `M'` | `M'（2R）` | 3 阶中层有公认单字母记法，规范字符串就是 `M`/`E`/`S` |
| 4 阶内层 | `2R'` / `2L'` | `2R'（M）` / `2L'（M'）` | 4 阶内层无公认单字母，用 `2R`/`2L` 族 |

两族**不会在同一次运行内混用**（阶数是固定的）。日志、角标、API `move` 字段三处只用规范族；括号别名只出现在状态栏与按钮副标题。这条不是洁癖：「三处同一字符串」是我们防「UI 和 API 各拼一套」的唯一手段。

**列的固定宽度**：`4ch | 6ch | 5ch | auto`。用 `tabular-nums`。禁止用 flex 自动分配——日志的扫描价值全在列的严格对齐。

> **第 2 列定 `6ch`（已确认）**：最长指令是 `3Rw'` / `3Rw2` = **5 字符**，`6ch` 装得下。不缩到 `4ch`，因为缩了就必须把 3 层宽转改成 `3r'` 这类小写记法，而「日志指令列 / API `move` 字段 / 角标」三处必须是同一字符串（§0 结论 5），改记法会同时破坏三处。

**「待定行」态**（双击归并专用，详见 §5.5）：`opacity: 0.55` + 结果列一个 6px `--fg-3` 圆点；归并或超时后**就地变形**为定稿，**行高与行号永不变化**。禁止用「删行 + 插行」实现归并——那会产生高度塌陷与展开，等价于闪回帧。

**新条目进入方式**（这是最容易做错的地方）：

| 用户位置 | 行为 |
|---|---|
| 已滚到底部（距底 <40px） | **自动追加 + 自动滚到底**。新行：`translateY(4px)` + `opacity 0→1`，`--dur-enter` / `--ease-out`；同时该行背景闪 `--log-new-flash`，200ms 后消退 |
| 用户手动上滚了（距底 ≥40px） | **禁止自动滚动**（否则用户在查历史时会被拽走）。改为在日志区底部悬浮一条 `42 条新记录（点击回到底部）` 的提示条 |
| 用户点提示条或滚回底部 | 恢复自动追加，提示条消失 |

**结果标记**：**不用左边框色条**（这是「圆角卡片 + 彩色左边框」反模式的变体，被禁）。改为：
- 状态列用图标（16px 描边对勾 = `--log-ok-fg`；16px 描边叉 = `--log-bad-fg`）+ 单字符文本 `OK` / `NO`。
- 整行底色不变。异常的可见性靠「图标 + 文本」，双通道冗余，色盲安全。

**空状态**：`还没有操作记录` + 一行 `按键盘或点击下方按钮开始`，居中，`--fg-3`，`--text-sm`。不做插画。

**溢出**：虚拟滚动阈值 200 行（超过则只渲染可视区 ±20 行）。日志同时是回放数据源，不能截断数据，只能截断渲染。

#### 7.4.3 「可提交」态（PRD §7.4 的独有中间状态，必须单独设计）

PRD 规定：`applyMove` 后检测到已还原**不直接终止**，只给视觉提示并置为 `solved_pending`（「可提交」）。这是一个独立状态，原设计遗漏了。人类默认 `auto_submit_on_solved=true`，会立即结算；Agent 默认等待显式 `submitSolution()`。

| 维度 | 设计 |
|---|---|
| 触发 | 每次 `applyMove` 后引擎判定 `isSolved === true` 且 `result` 尚未落定 |
| 中栏 | 魔方外轮廓一圈 3px `--success` 描边，**常驻不闪**（不是动效，是状态）。视角条下方出现一个 `已还原，可提交` 的小 pill（`--badge-solved-*`） |
| 状态栏 | `已还原 · 点「提交解答」提交，或继续旋转视角` |
| 提交按钮 | 左栏会话控制区的主按钮由 `结束` 变为 `提交解答`（白实心，`--action`）；原 `结束` 降为次按钮 `放弃` |
| 键盘 | **`running` / `solved_pending` 态 `Enter` 无绑定**（PRD v1.2 / v1.10）。提交只能点按钮——因为误按 `Enter` 会产生一次 `NOT_SOLVED`，累计 3 次直接终止挑战 |
| 继续操作的后果 | 用户仍可旋转视角（`rotateView` / `observe` 允许），但**不可再做 `applyMove`**（返回 `ALREADY_SOLVED`，AC-75）。拖动视角不会让描边与 pill 消失；两者只随提交/结束清理 |
| 配置开关 | 「还原后自动提交」默认人类模式开启、Agent 模式关闭（PRD §7.4）。开启时跳过本状态直接结算，但结算前仍显示 300ms 的描边作为反馈 |

#### 7.4.4 结果面板必须携带的诚实标注（PRD §9.2，**6 条标注 + 1 个折叠区，不可配置关闭**）

位置：结果面板最底部，`--text-xs` / `--fg-3`，1px `--border-subtle` 上分隔，行距 `--space-2`。

| # | 标注原文 | 出现条件 |
|---|---|---|
| 1 | `本机测量，未经服务端校验` | **恒显示** |
| 2 | `难度为启发式估计，非最短解距离` | **恒显示** |
| 3 | `本模式用于防止误看，不能阻止通过开发者工具读取内存。` | 蒙尘开启时 |
| 4 | `蒙尘只防误看，不防逆向；本次结果不构成模型能力的强证据。` | 蒙尘开启时（PRD §8.4） |
| 5 | `本次题面由随机操作生成，非均匀随机状态，不构成标准化难度基准。` | `gen_mode === "random_moves"` 时 |
| 6 | `本次运行包含 {N} 次暂停（共 {M} 秒），计时已扣除。` | `pause_count > 0` 时（AC-59） |
| 7 | `其他计步口径`折叠区（`HTM-layer` / `QTM`） | 恒显示，默认收起 |

**三条实现约束**：

1. **第 5 条与第 6 条的位置不同。** 第 5 条在底部脚注区；**第 6 条必须出现在结论区下方**（结论区就是「已还原 / 超时 / 步数耗尽 / 已放弃 / 提交无效 / 未完成 / 内部错误」那行大字下面），因为它解释的是「这次成绩是否可与别的运行直接比」，而脚注是「数据怎么读」。把第 6 条塞进脚注 = 用户根本不会看到暂停对可比性的影响。
2. **第 7 条用 Segmented 分段控件，不用下拉。** 只有 `HTM` / `HTM-layer` / `QTM` 三个选项，且要**并排对比**——下拉会把两个非默认口径藏起来，用户不会去点。默认 `HTM`。切换只影响这一屏的展示与对比表排序，**不回写记录、不影响判定**（PRD §7.1）。
3. **6 条标注 + 1 个折叠区全部不可被配置关闭。** 设置浮层里不提供任何「隐藏数据说明」的开关。这不是产品洁癖：这个纯前端评测产品唯一能守住的资产是诚实，关掉说明等于关掉唯一的差异化。

> 这段话请写进实现注释：「这些标注不是免责声明，是产品定位的一部分。设计上要做的是让它可读但不喧宾夺主——`--fg-3` + 12px + 位于折叠线下方，需要时能查到，不需要时不占注意力。」

| **`interrupted`（上次未正常结束）** | 进入页面时右上角一条可关闭的提示条：`有一次未完成的运行（3×3 · 约 2 分钟前）` + `查看记录` / `忽略`。**不静默丢弃**（PRD §7.3） |
| **`localStorage` 不可用**（隐私模式 / 配额满，PRD §9.3） | 顶部常驻非阻塞提示条：`浏览器存储不可用，本次结果不会被保存。可在结果页复制结果摘要手动留存。`**功能不降级**——挑战照常可跑，只是不落盘。进度条与按钮全部保持可用 |
| **无历史运行**（PRD §9.3） | 历史区：`还没有运行记录。创建第一个挑战后，这里会按时间倒序列出结果。` + `创建挑战` 按钮。**不用「暂无数据」**——PRD 明确禁止这类空洞占位 |
| **结果记录损坏**（PRD §9.3） | `这次运行的记录无法读取` + `删除该记录` / `复制原始数据`。不做静默丢弃 |

### 7.6 Agent 连接 / 调用状态

右栏顶部独立区块「Agent 会话」，`--elev-1`，内部用 `border-subtle` 分行。**这是评测平台的可信度中心，数字要密。**

```
Agent 会话                                    ● 未连接
─────────────────────────────────────────────────────
工具调用    —       观察    —       操作    —
平均单步    —       最近心跳 —
```

| 状态 | 状态点 | 文案 | 附加视觉 |
|---|---|---|---|
| `idle` 未接入 | `--agent-dot-idle` 8px 实心圆 | `未连接 Agent` | 无 |
| `ready` 已连接待命 | `--agent-dot-ready` | `已连接 · 等待首次观察` | 无 |
| `busy` 请求中 | `--agent-dot-busy` | `observe() · 已用 240ms`（方法名用等宽，耗时实时递增） | 右栏顶部 1px 高的**不确定进度条**（`--agent-progress-h`，`--accent` 段平移）。**不用 spinner** |
| `stale` 空闲超时 | `--agent-dot-stale` | `已 12s 无请求 · 建议检查 Agent` | 无 |
| `offline` 断连 | `--agent-dot-offline` | `连接已断开` + 次按钮 `重试` | 无 |
| `submit_fail_1` / `submit_fail_2` | `--agent-dot-stale` | `提交未通过（第 1/2 次）· 可继续操作` | 操作区上方 3 个机会圆点，已消耗的转 `--danger` |
| `finished` | `--success` / `--danger` | `运行已结束 · {result 中文}` | 右栏整体切为结果面板（§7.4.1） |

> 方法名对齐 PRD 的工具集（9 个）：`getChallengeInfo` / `observe` / `rotateView` / `applyMove` / `getLastActionResult` / `getProgress` / `submitSolution` / `getChallengeResult` / `abandonChallenge`。
> **`submitSolution` 失败两次不终止**（PRD §7.3），所以 UI 必须能在右栏显示「这是第几次失败、还剩几次」——这是原设计遗漏的一条，它直接决定 Agent 会不会因为一次误判就丢掉整局。

数据区始终显示四个计数（`工具调用 / 观察 / 操作 / 平均单步耗时`）+ `最近心跳`。未接入时全部显示 `—`（em dash，不是 `0`——`0` 会被误读成「调用过 0 次」，`—` 正确表达「无此数据」）。

**必须显示 `上一次观察 ID`**（`obs-a91f`，等宽，可复制）。这是 Agent 操作的溯源锚点，也是这个平台区别于普通魔方游戏的核心信息。

### 7.7 暂停态（`paused`，PRD §7.2.1，F18 已升 P0）

> 这是 PRD v1.9/v1.10 的真暂停：画面与计时**同时冻结**。代价是暂停给了人类额外思考时间，而 Agent 没有等价能力；因此结果页必须显示 `pause_count` / `paused_total_ms`（PRD §8.5 / AC-59），让跨运行对比时暂停时长可见。

#### 7.7.1 左栏按钮组的变化

| 状态 | 主按钮 | 次按钮 | 弱按钮 | 备注 |
|---|---|---|---|---|
| `ready` | `开始挑战`（白实心） | `复现题目` | `放弃` | 副文案 `按 Space 开始` |
| `running`（人类） | `暂停`（`--btn-secondary`） | `结束挑战`（`--btn-danger` 描边） | `放弃` | 主按钮位给「暂停」，因为它是高频动作 |
| `running`（**Agent**） | —— | `结束挑战` | `放弃` | **不渲染暂停按钮**（AC-58）。主按钮位空出来，改显示 `Agent 运行中` 的静态徽章 |
| `paused` | `继续`（白实心） | `结束挑战` | `放弃` | 主按钮变回白实心 |
| `finished` | `回放过程`（白实心，在右栏结果面板） | —— | —— | 左栏只留 `再挑战一次` |

**「暂停」用次要样式而不是主样式**：主按钮位是留给「推进流程」的动作（开始 / 继续 / 回放）。暂停是「中断流程」，给它主按钮位会让用户误以为它是这一屏该做的事。

#### 7.7.2 中栏的暂停视觉（三条同时生效）

| # | 做法 | 为什么 |
|---|---|---|
| 1 | **3D 冻结在暂停前最后一帧**，不渲染新动画、不响应拖拽、不响应方向键（`rotateView` 返回 `PAUSED`，AC-57） | 画面冻结与计时冻结必须一致，不能让用户误以为还有思考时间 |
| 2 | 冻结的画布上加一层 `--bg-page` 20% 半透明遮罩 + 全部 HUD / 矩阵按钮 `opacity: 0.4` + `aria-disabled="true"` + `pointer-events: none` | 让「现在不能操作」一眼可见。20% 而不是 60%：因为用户已经看到的画面就在那里，重度遮罩会让人以为「题面被收回了」——而暂停**不收回**题面 |
| 3 | 画布中上部一条半透明提示条（`--bg-float` 92% + `--elev-2`），**两行**：<br>第一行 `挑战已暂停`（`--text-md` / `--fg` / 600）<br>第二行 `计时已冻结`（`--text-sm` / `--warn` / 500） | **第二行不能省**（PRD §7.2.1 / AC-73 明确暂停冻结计时）。用 `--warn` 而不是 `--danger`：这不是错误，是规则 |

**倒计时数字与倒计时条同时冻结**（§7.1 / AC-73）：暂停态下数字保持 `--timer-fg` 不变色，但数值与进度条都不再变化；恢复后从冻结点继续。把“数字继续跳”实现进来会直接违反 PRD v1.9/v1.10。

#### 7.7.3 被拦截操作的反馈文案（PRD 要求逐字）

| 触发 | 反馈 | 位置 |
|---|---|---|
| 在 `paused` 态点击任何转动按钮 / 拖拽视角 / 按面键 | **`挑战已暂停。计时已冻结。`**（逐字，两句话都在） | 操作区头状态栏，1500ms 后回 `就绪`；不弹 toast、不弹 dialog |
| 在 `paused` 态按 `Space` | `Space` 在暂停态无绑定；暂停/继续只走界面按钮 | —— |

**为什么用状态栏而不是 toast**：用户在暂停态会**反复点**（这是人的本能：「我点了为什么不动」）。toast 每次弹一次会变成骚扰；状态栏是同一个位置持续显示，点十次看到的是同一句话，不会烦躁。

#### 7.7.4 暂停在别处的可见性

| 位置 | 表现 |
|---|---|
| 左栏计时区 | 计时器旁一个 `已暂停` 静态小标签（`--warn`），下面一行 `已暂停 2 次 · 共 47s`（仅在 `pause_count > 0` 时出现，`--text-xs` / `--fg-3`） |
| 操作日志 | 追加一条 `type:"pause"` 的行：`#--  PAUSE  12:04.31`，同样式追加 `RESUME`。**它们不是转动，序号列显示 `--`**，不计步 |
| 结果面板 | 第 5 条诚实标注（§7.4.4） |
| 回放 | 时间轴上 pause / resume 各一个短竖线标记（`--warn`），与观察点（`--accent`）区分颜色 |

### 7.8 配置页（创建挑战）的文案约束

配置页不是本设计的重点（一屏表单），但有一处**必须管住**：题目来源的措辞。

| 字段 | 选项 | 说明 |
|---|---|---|
| 题目来源 | `随机打乱` / `固定题目` / `指定 seed` / `导入` | **只有这四个** |

**禁止出现的措辞**（PM + 架构裁决，v1 只做随机操作打乱，不做均匀随机状态生成）：

| 禁止 | 为什么 |
|---|---|
| `随机状态` / `均匀随机` / `标准化题面` / `标准化能力测试` | v1 做不到均匀随机状态生成（需要求解器与被控状态空间采样）。写了就是承诺了做不到的事 |
| `随机打乱（标准）` 这类加括号暗示「这是标准做法」的变体 | 同一个意思的软化包装，一样不行 |

**结果页配套**：`gen_mode === "random_moves"` 时的强制标注（§7.4.4 第 4 条）已改为 `本次题面由随机操作生成，非均匀随机状态，不构成标准化难度基准。`——这句把 v1 从「标准化能力测试」的定位上摘下来了，是基于诚实性必须付的代价，**不得软化**。

> 设计侧的执行动作：配置页的这一组单选/分段控件，**选项文案直接从 PRD 的枚举值取，不自行润色**。这是我给前端的明确要求——文案一旦被「优化」成更顺口的说法，PRD 的边界就漏了。

## 8 · 响应式

> **依据修正**：PRD §4 已把「移动端深度适配」列入 Out-of-Scope，§11 把「最小窗口 1280×720」定为 P0 兼容性要求。
> 因此本章不再承诺移动端可用，改为三档桌面契约 + 一档「不崩即可」。

### 8.1 最小支持窗口的硬约束

`1280×720` 是最小支持窗口，必须在 720px 高度内**同时容纳**：操作区头 44px + 3D 舞台 + 转动矩阵 168px。所以：

- `--stage-min-h` 在 720px 高的窗口下会挤压矩阵 → **矩阵高度优先于舞台高度**。实现顺序：先固定头部 44 + 矩阵 168，剩余全部给舞台（720 − 44 − 168 − 左右栏内边距 ≈ 480px，够用）。
- 若视口高度 < 640px：矩阵切到「紧凑高度」116px（面卡标题隐藏，只留三键 + 角标），并提示一次 `窗口过矮，建议最大化`（`--fg-3`，不可关闭 3s）。

### 8.2 三档桌面契约 + 一档兜底

| 断点 | 三栏布局 | 中栏矩阵 | 关键调整 |
|---|---|---|---|
| **≥1440px** | `340px \| 1fr \| 392px`，用 1px `--border-subtle` 做视觉分隔（不用 gap 留白） | **L3（3 列 × 2 行）**，按钮 `56×40`，角标完整形态常显 | 全信息态。右栏三段（观察数据 / 操作日志 / Agent）全部展开；迷你键位图默认展开 |
| **1280–1440px** | `300px \| 1fr \| 352px` | L3，按钮 `52×40`，角标常显但前缀降级 | 左栏「已用时间」并入「剩余时间」副行；右栏 Agent 区收为 2 行紧凑；迷你键位图默认折叠 |
| **1024–1280px**（尽力档，不承诺） | `264px \| 1fr \| 312px` | **L2（2 列 × 3 行）**，按钮 `48×40`，角标 hover 显示 | 右栏「观察数据」收为可展开的一行摘要；日志保留常显；**开始前提示一次**「窗口宽度低于 1280，部分区域会变紧」 |
| **<1024px**（兜底，只保证不崩） | 单列纵向流：`信息条（吸顶）` → `舞台` → `矩阵` → `右栏` | L2，按钮 `44×44`，矩阵允许横向滚动 | 只保证「能看能转」，明确不作为契约。移动端不做手势转层、不做竖屏三栏改版（PRD §4） |

### 8.3 明确不做的（对齐 PRD §4 Out-of-Scope）

| 不做 | 依据 |
|---|---|
| 触屏手势转层（滑动转层） | PRD §4 明确 Out-of-Scope：手势与视角拖拽冲突，误触率高 |
| 竖屏三栏改版 | 同上 |
| 底部 TabBar | 这不是多页面导航，是一个工作台 |
| 3D 视角的陀螺仪支持 | 手持姿态变化会让魔方乱转，干扰「看某一面」的目的 |
| 移动端 4×4 的 G4/G5/G6 三个 tab 与层选择器 | 控件密度不足，tab 置灰并提示 `建议在桌面端操作` |
| 移动端性能调优 | PRD §4 明确 Out-of-Scope；仅做 `devicePixelRatio` 上限 1.5 的降级 |

### 8.4 兜底档的最低验收（三条，不多求）

1. 3D 舞台高度 ≥320px，魔方能完整显示（不裁切）。
2. 18 个转动按钮全部可达（允许横向滚动，滚动容器有 `--border-subtle` 边提示可滚）。
3. 吸顶信息条恒显 `剩余时间` 与 `步数`（这两项是「能不能用」的分界线）。

## 11 · 回放界面（PRD §10）

> 回放不重跑逻辑，只重放事件流（PRD §10.1）。设计上的第一原则：**复用现有三栏，不做一个独立外壳**。切换只改一个 `mode` 属性，中栏的转动矩阵被播放控制条替换，其余结构不动。理由：回放是「看数据」，转动是「造数据」，两者共享同一个 3D 场景、同一套 HUD、同一套 Token；独立外壳会产生第二套布局代码和第二套视觉，而它只被用一次。

### 11.1 布局（复用三栏，`mode = "replay"`）

```
┌ 左栏 · 回放信息 ─────┬ 中栏 · 3D + 播放控制 ──────┬ 右栏 · 日志联动 ──────┐
│ 题面 cb3-7f21a9      │                            │ 操作日志               │
│ 3×3 · 随机状态       │        （3D 场景）          │  当前步高亮并滚到可视区 │
│ 人类 · 1:42.37       │                            │  高亮行：--accent-soft │
│ 68 步 · TPS 0.66     │  ┌─ 视角模式 segmented ─┐   │  左侧 2px 指示？→ 不用  │
│ 引擎 v1.0.0          │  │ 上帝 观察者 校验     │   │  改用整行底色 + 序号加粗│
│ ─────────────────    │  └──────────────────────┘   │                        │
│ 显示开关             │                            │ 观察点列表             │
│  [x] 步数            │  ┌─ 播放控制条 56px ──────────────────────────┐
│  [x] 时间            │  │ [▶] [⏮] [⏭]  ━━━━●━━━━━  1×  00:41/01:42 │
│  [ ] 观察发生点      │  └────────────────────────────────────────────┘
└──────────────────────┴────────────────────────────────────────────┘
```

### 11.2 播放控制条（替换转动矩阵，`height: 56px`）

| 控件 | 行为 | Token |
|---|---|---|
| 播放 / 暂停 | 按事件时间戳**等比压缩**播放，默认把总时长压到 20–40 秒 | `--btn-ghost-*`，图标 20px |
| 上一步 / 下一步 | 单步前进/后退（每步执行一次正/逆操作） | 同上 |
| 进度条 | 可拖拽跳到任意步；跳转靠最近关键帧快进 | 轨道 `--bg-card` / 已过 `--accent` / 滑块 12px `--accent` |
| 速度 | `0.5×` / `1×` / `2×` / `4×`，Segmented | 4 段，`--text-sm` |
| 时间读数 | `当前时间 / 总时长` + `当前步 / 总步`，等宽 `tabular-nums` | `--font-mono` / `--fg-3` |

**播放控制条不能用浮层**：它在回放中是最高频的交互区，必须常驻在拇指/鼠标自然落点（中栏底部，即原矩阵位置）。做成 3D 上的悬浮 HUD 会与视角拖拽抢手势。

### 11.3 三种视角模式（`segmented`，PRD §10.3）

放在中栏 3D 场景**左上角**（原「打乱/重置」的位置——回放态这两个按钮不存在，位置空出来了）。**默认 = 上帝视角。**

| 模式 | 渲染规则 | 设计要点 |
|---|---|---|
| **上帝视角** | 全开颜色，看完整过程 | 默认。用户第一次进回放看到的应该是「完整真相」 |
| **观察者视角**（差异化第 2 位，**优先做**） | 按该次运行的 `observation_mode` 重现「Agent 当时能看到什么」。未授权面**复用 §6.3 的 dust 材质** | 这是回放最有价值的模式：能直观看出「Agent 在单面观察下做了多少盲猜」。**它复用蒙尘材质，不新增一套「不可见」视觉**——「蒙尘」这个符号在用户心里只定义一次：**这块我不能看** |
| **校验视角** | 每步显示操作前后 6 面颜色矩阵的差异高亮 | 用于人工核验引擎正确性。差异贴纸描边 2px `--warn`；右栏底部展开一个 6 面 facelet 网格对比（前 / 后 / 差异），仅在选中本模式时出现 |

**为什么观察者视角优先做**：上帝视角是「任何魔方播放器都有」的能力，不构成差异；观察者视角直接回答「这个 Agent 在受限观察下表现如何」，是本产品评测定位的核心展示面。而且实现成本低——它只是「把 dust 材质按 observation_mode 重新套一遍」，渲染路径已有。

### 11.4 时间轴与观察点

- 进度条上三重叠标记：
  - 普通转动事件：1px `--fg-disabled` 小刻度
  - **观察点**（`observation_id` 发生处）：4px 高的 `--accent` 竖线，仅在「显示观察发生点」开启时渲染
  - **pause / resume**：4px 高的 `--warn` 竖线
- 刻度下方按需显示时间戳与累计步数（受「显示步数 / 显示时间」两个开关控制）。
- 日志联动：当前步在右栏日志中**整行底色 `--accent-soft` + 序号加粗**，并自动滚动到可视区。**不用左侧色条**（§9 第 7 条禁止侧条纹）。
- 用户手动滚动日志时，**暂停自动滚动**，改为底部 `回到当前步` 提示（规则同 §7.3 的日志滚动策略）。

### 11.5 回放的边界提示（PRD §10.4，三条都要有 UI）

| 情况 | UI |
|---|---|
| `engine_version` 与当前不一致 | 进回放前弹一次确认层（`--z-modal`）：`本次运行由旧版引擎生成，回放结果可能与当时不完全一致` + 主按钮 `仍要回放` / 次按钮 `取消`。**不静默播放** |
| 事件数超 2000 条被截断 | 回放页顶部常驻一行 `记录已截断（仅保存前 2000 条），进度条末端为最终状态`（`--fg-3`） |
| 缺少回放数据 | 中栏替换为空态：`该记录缺少回放数据` + `仅可查看结果`，不给重试按钮 |
| 记录损坏 | `这次运行的记录无法读取` + `删除该记录` / `复制原始数据`（PRD §9.3）。不静默丢弃 |

**回放不修改任何原始记录**（PRD §10.4）：回放中是 `mode="replay"`，`applyMove` 路径被替换为「读事件 → 应用状态」，**任何点击都不产生新事件**。UI 上要在首次进入时用一行 `回放模式 · 操作不会改变记录` 明示——这行字避免用户以为自己把历史改坏了。

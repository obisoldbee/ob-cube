## 1 · 设计方向与对标

### 1.1 寄存器判断（第一步必判）

| 维度 | 判断 | 依据 |
|---|---|---|
| 寄存器 | **Product（产品型）** | 这是一个工具 UI / 仪表盘 / 竞技场，用户每天进来做事，不是进来被说服 |
| 平台轴 | **web，桌面优先** | PRD 明确「第一版优先保证桌面端操作效率」 |
| 色彩策略 | 克制：着色中性色 + 一个强调色 ≤10% 表面积 | Product 寄存器规则 |
| 排版策略 | Sans-Serif 为主，**Dashboard 上 Serif 严格禁止** | Product 寄存器规则 |
| 动效策略 | 功能性为主，150ms 收敛值；唯一例外是蒙尘解锁 600ms | Product 寄存器规则 |
| 图片策略 | 不用照片。视觉主体是 3D 魔方本体 + 数据可视化 | 零图片不是 bug：这个产品的「图」就是魔方 |

### 1.2 三轴设计刻度

| 刻度 | 取值 | 说明 |
|---|---|---|
| `DESIGN_VARIANCE` | **3** | 三栏**非对称**宽度 `340 / 1fr / 392`，中栏最大且不等宽；中线不居中。不做到 4 以上的原因：这是高频操作工具，布局必须可预测，任何「艺术化留白」都会拖慢操作。 |
| `MOTION_INTENSITY` | **5** | 转动动画 + 状态过渡 + 一次蒙尘仪式。不做持续微动画（脉冲 / 浮动 / 呼吸），因为持续动画会和「计时器在跑」这个真实信号混淆。 |
| `VISUAL_DENSITY` | **7** | 接近驾驶舱模式：面板内用 `border-subtle` 的 1px 线分隔数据，不用卡片套卡片。真正的「卡片」全站只有 3 种：结果面板内的结论块、面卡、浮层。 |

### 1.3 竞品调研（4 个，实查）

| 产品 | 布局 | 配色 | 值得借 | 不能借 |
|---|---|---|---|---|
| **csTimer** | 单列大计时器居中，logo 旁 6 个图标按钮打开三个可自动隐藏面板（打乱 / 成绩 / 工具）；移动端切 `mtds`，紧凑版切 `cspt` | 内置 8 个可配色属性 + 5 套 LCD 数字字体模板，默认浅色 | 「计时中自动隐藏面板 → 计时结束自动显现」的**专注态切换**；「LCD 整数大 / 小数小」的数字层级；三档 UI 密度模式 | 视觉是 2013 年的：靠渐变和阴影做拟物，信息全靠一列堆。它没有「三栏同时可见」的能力。 |
| **CubeDesk** | 现代三栏，计时器居中，左 session / 右成绩列表；含 focus mode、analytics 图表页、alg trainer、1v1 | 主题可自定义主/次色，默认绿+蓝；自称对标 Apple UI / Toggl 的柔和感 | **「现代感来自留白和圆角一致性，不来自特效」**；focus mode 把一切非必要元素隐去；统计页用图表说话 | 它的商业重心在训练和统计，操作层只有「打乱 + 计时」。我们需要的操作按钮矩阵它完全没有可参照物。 |
| **Twisty Timer** | 移动优先单列，大计时器 + 底部 tab | 深色为主，单一强调 | 触摸目标大、状态即时；深色默认对长时间使用友好 | 移动单列，桌面三栏无参考价值 |
| **Linear** | 左侧窄边栏 + 中间列表 + 右侧详情；**非对称三栏** | 近黑底（`#08090A` 级）+ 4 级灰阶文字 + 1px `rgba(255,255,255,0.05~0.08)` 描边；强调色占用面积极小 | **这是本项目的主对标**：① 三栏宽度非对称；② 层级靠**亮度递进**不用阴影；③ 1px 半透明描边代替实线边框；④ 数字用等宽 + `tabular-nums`；⑤ 快捷键角标内嵌在按钮里（`kbd` 风格 chip） | 它的强调色是 Indigo 系——本项目不用（专家团 P0 禁止 + 业界公认 AI 首罪）。它的「极简到几乎无操作感」也不适合一个要按 18 个键的工具。 |

**对标结论**：以 **Linear** 为设计语言来源（密度、层级、描边、数字排版、kbd chip），以 **csTimer** 为交互机制来源（专注态切换、计时器数字层级），以 **CubeDesk** 为质感校准（圆角与留白一致性）。三家都没有解决的问题——**3D 操作按钮矩阵**——是本项目要自己原创的部分，见 §4。

### 1.4 视觉主题与氛围

- **关键词**：冷静、精密、可校验、有摩擦感
- **氛围一句话**：像坐在一台校准过的竞技计时台前面——四条 1px 的线把屏幕切成「规则 / 操场 / 遥测」三个区，魔方是唯一有颜色的东西，其余全是灰阶。你的每一次按键，都在遥测区留下一行不可编辑的记录。
- **物理对象参照**（用于后续字体与材质决策）：体育馆翻页计时牌、秒表机芯、旧式塔钟的刻度盘

## 2 · 设计 Token 体系

> **本文档中的色值表是 `design/design-tokens.css` / `design/design-tokens.json` 的只读镜像**，用途是评审与核对，不构成第二处定义点。代码层（Phase 3）引用色值的唯一合法来源是这两个文件里的 `var(--token)`；本文档表格里的 hex 不得被复制进任何组件代码。组件层出现裸 hex = 违规。

### 2.1 三级结构

```
Primitive（原始值）        --grey-0..11 / --cyan-400..600 / --white-cta / --green-ok / --cube-*
      ↓  仅 semantic 层可引用
Semantic（语义）           --bg / --bg-panel / --fg / --fg-2 / --accent / --border / --success ...
      ↓  仅 component 层可引用
Component（组件）          --btn-turn-bg / --timer-fg-warning / --log-row-h / --agent-dot-busy ...
      ↓
页面代码：只允许引用组件层或语义层，禁止引用 primitive 层，禁止裸值
```

四层架构映射：Primitive = A1-identity + A1-structure；Semantic = A2；Component = B-slot + C-extension。

### 2.2 背景层级（5 级 + 1 个舞台专用）

深色主题靠**亮度递进**表达层级，不靠阴影。相邻 ΔL\* 全部 ≥ 2.1，肉眼可分辨（实测）：

| 序号 | Token | 色值 | CIE L\* | 相邻 ΔL\* | 用途 |
|---|---|---:|---:|---:|---|
| 1 | `--bg-sunken` | `#08090C` | 2.47 | — | 输入框底、日志滚动区、代码块、kbd chip |
| 2 | `--bg` | `#0D1015` | 4.61 | +2.14 | 页面底 |
| 3 | `--bg-panel` | `#141922` | 8.65 | +4.04 | 三栏面板底 |
| 4 | `--bg-card` | `#1B222C` | 12.98 | +4.33 | 卡片、转动按钮填充、hover 底 |
| 5 | `--bg-float` | `#252D3A` | 18.26 | +5.28 | 悬浮层、popover、dropdown、快捷键浮层 |
| 6 | `--bg-stage` | `#0B0E14` | 3.94 | — | **3D 舞台专用底**。刻意比 `--bg-panel` 更暗，让六色贴纸的对比度最大化；它不属于 5 级递进，是独立色 |

> **为什么输入框底比页面底更暗**：凹槽语义。控件「陷进去」比「浮起来」更符合「这是我要往里填东西」的直觉。它的可识别性由 `--border-control`（3.37:1）承担，不靠填充差。

### 2.4 强调色与语义色

| Token | 色值 | L\* | vs panel | 语义 | 允许出现的位置（每屏 ≤2 处） |
|---|---|---:|---:|---|---|
| `--accent`（信号青） | `#1ED0C0` | 75.6 | 9.09:1 | 进行中 / 实时 / 选中 / focus ring | ① 选中的 tab 下划线 ② 计时器进度条 ③ `:focus-visible` 环 ④ 日志新行底闪 |
| `--action`（主操作白） | `#EDF1F5` | 95.0 | 15.52:1 | 主 CTA 实心 | 每屏 1 处：「开始挑战」/「再挑战一次」 |
| `--success` | `#3FD07A` | 74.6 | 8.82:1 | 还原成功、操作合法 | 结果面板结论区、日志成功标记 |
| `--warn` | `#F0B429` | 76.9 | 9.45:1 | 剩余 ≤60s、输入队列积压 | 计时器数字、步数数字 |
| `--danger` | `#FF5D57` | 61.5 | 5.84:1 | 超时、非法操作、断连 | 结果面板结论区、日志失败标记、危险按钮描边 |
| `--live` | `#7AB8FF` | 73.3 | 8.50:1 | Agent 已连接待命 | Agent 状态点 |

**为什么强调色是青而不是 Indigo / 紫**：
1. 魔方六色已占满 白 / 黄 / 绿 / 橙 / 蓝 / 红 六个色相区，青是唯一没被占用的高可辨色相。强调色只要不落在六色里，就永远不会和贴纸抢注意力。
2. Tailwind 默认 Indigo 500（`blue-600` 系以下最常被直接拿来当强调色的那一个）是 AI 模板首罪，禁用；本方案连 Indigo 纯色都不用，避免任何联想。
3. 青 = 遥测 / 仪表 / 医疗监护的通用语言，与「评测平台的实时读数」语义同构。

**结构性硬约束（写进代码 review checklist）**：
> 3D 舞台区（`--bg-stage` 覆盖的画布范围，含其外扩 16px）内**禁止出现任何 `--accent` 色元素**。画布内的颜色只能来自 `--cube-*`。

这条规则把「强调青 vs 绿贴纸」的潜在混淆从根上切断——实测 `--accent`(L\*75.6) 与 `--cube-F`(L\*74.0) 的 L\* 只差 1.6，如果它们同处一屏且相邻，会误读。靠空间隔离解决，不靠调色。

**唯一例外（已评审放行，不得扩展）**：当前转动层的轮廓描边（§5.3 的 L2）。它是覆盖在贴纸之上的线，必须与六色全部冲突才看得见，生命周期只有 `--dur-turn`，且有明确功能目的。除它之外，画布内不允许出现任何 accent 色元素。

#### 2.5.2 实测区分度（脚本 `docs/research/_color-math.py` 可复算）

**L\* 阶梯**（灰度化后仍可分辨的唯一保证）：

```
U 白  97.11
D 黄  82.66   Δ 14.46
F 绿  73.99   Δ  8.66
L 橙  66.12   Δ  7.87   ← 全六色最小间隔
B 蓝  56.53   Δ  9.60
R 红  46.97   Δ  9.56
```

| 指标 | 实测值 | 判定 |
|---|---|---|
| 两两最小 ΔL\* | **7.87** | 全色盲（achromatopsia）在灰度下仍可区分 |
| 两两最小 ΔE(CIE76) 正常视觉 | **40.0** | 远超 JND（≈2.3），清晰可辨 |
| 红↔绿 ΔL\* | **27.0** | 红绿色盲的核心补偿来源 |
| 全部六色在 stage 上最小对比度 | 3.86:1（R 红） | 满足非文本图形 3:1（WCAG 1.4.11） |
| deutan（绿色盲）最差对 | D 黄 vs L 橙 ΔE 14.8，但 ΔL\* 12.33 | 靠亮度可辨 |
| protan（红色盲）最差对 | D 黄 vs L 橙 ΔE 23.4 | 可辨 |
| tritan（蓝色盲）最差对 | L 橙 vs R 红 ΔE 24.3 | 可辨 |

#### 2.5.3 色盲友好方案（结论 + 数据 + 被否方案）

**结论：三级补救，第一级是设计本身，不是开关。**

| 级别 | 手段 | 状态 | 覆盖的障碍类型 |
|---|---|---|---|
| **一级（默认生效，无开关）** | 六色亮度阶梯 ΔL\* ≥ 7.87 | 必须 | deuteranopia / protanopia / tritanopia / achromatopsia 全部 |
| **二级（默认生效 · 面中心标记）** | 每面**中心贴纸**叠加该面字母（`U D F B R L`，`--font-mono`、`--cube-body` 色）。3×3 用中心块；2×2 无中心块，故 4 张全标；4×4 的 4 个中心块各标 | **默认开启，无开关**（不可关） | 满足 PRD §11 可访问性 P1：「颜色差异同时有面名标注」——保证「操作本身不以颜色为唯一信息载体」 |
| **二级半（开关「每张贴纸标记」）** | 所有贴纸都标字母，贴纸最短边 ≥18px 时渲染，视角缩小时自动隐藏 | 开关，默认关闭。**位置：右上角设置浮层的「显示」分组**，不占主界面 | 红绿 / 黄橙混淆，以及需要绝对确定性的场景（如录屏讲解） |
| **三级（开关「单色模式」）** | 六色替换为 6 级灰阶（直接取 L\* 阶梯 `#F4F7FB / #D6D9DD / #B4B8BD / #91969C / #71767C / #52575E`） | 开关，默认关闭。**位置：同上设置浮层「显示」分组**，与二级半相邻 | 全色盲；也是打印/低色域屏幕的兜底 |

**为什么不做「切换配色方案」（换一套红绿替代色）—— 被否方案，理由给数据**：

实测将 R 红 → 品红 `#F05DA0`、F 绿 → 青 `#22C8C0`、L 橙 → 紫 `#B07CF5` 后，在 deutan 模拟下最小 ΔE 反而从 14.8 掉到 **7.75（紫 vs 蓝）**。原因：红绿色盲把所有色相压成两簇（蓝黄轴），**任何色相替换都只是把冲突从一个对挪到另一个对**，无法消除。

同时，换配色会破坏玩家的色位肌肉记忆（标准魔方 U 白 / D 黄 / F 绿 / B 蓝 / R 红 / L 橙 是世界通用），对「普通玩家」这个核心用户的伤害大于对色觉障碍用户的帮助。

因此：**用亮度（理论上对全类型色觉障碍都成立）+ 字母标记（绝对冗余）+ 单色模式（极端兜底）**，而不动色相。

**描边/纹理为什么不作为主手段**：贴纸在 4×4 且视角缩小时，单张投影约 28px；斜纹在 28px 下会退化成噪点，反而降低可读性。所以纹理策略被否，改为字母（矢量、任意缩放下清晰）。但保留了 `--cube-sticker-edge: rgba(255,255,255,0.10)` 的 1px 内描边——它是用来在深底上防止 R 红丢轮廓的，不是色盲手段。

### 2.6 间距 / 圆角 / 阴影 / z-index

**间距（4px 网格，只允许下列值）**

| Token | 值 | 典型用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字、面卡内按钮间隙 |

缓动：

| Token | 曲线 | 用途 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认，确定、无回弹 |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入（浮层、日志行） |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退出 |
| `--ease-inout` | `cubic-bezier(0.65, 0, 0.35, 1)` | 跨屏（tab 切换、结果面板切换） |

#### 明令禁止：弹跳缓动 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`

三条理由，全部与本产品的核心约束直接冲突：

1. **它让「转动是否完成」在视觉上产生歧义。** 回弹曲线会先冲过目标位置再退回。而 PRD 第 1.2 条要求「每次转动都能被验证、记录和复现」——如果视觉上有一段时间魔方处在「转过了一点」的状态，用户无法判断引擎认为这一步完成了没有。**离散可校验的操作必须配确定性的动画。**
2. **它会累积成延迟感。** 玩家连续按键（3 步/秒）时，每步的 overshoot 段都会被下一步打断，产生持续的「甩尾」抖动。150ms 收敛值的前提是无回弹。
3. **前庭敏感用户对回弹最易不适。** overshoot 是唯一会产生「反向运动」的缓动，而反向运动是前庭系统最敏感的刺激类型。这是一个真实的无障碍代价，不是审美偏好。

替代方案：`--ease-out`（`cubic-bezier(0.16, 1, 0.3, 1)`）——减速曲线同样有「利落」的观感，但终点确定。

### 2.8 无障碍底线

| 项 | 规则 |
|---|---|
| 对比度 | 正文 ≥4.5:1（实测最低 6.09:1），大字 ≥3:1，非文本图形 ≥3:1（六色最低 3.86:1） |
| focus | `:focus-visible` 时 `0 0 0 2px var(--bg-panel), 0 0 0 4px var(--accent)`（双环，保证在任意底色上都可见） |
| 键盘 | 所有操作可键盘完成，见 §5 |
| 触摸 | 最小 44×44px（≥1440 时转动按钮 56×40 满足；<1200 时降到 44×40） |
| reduced-motion | `--dur-*` 全部归 0，转动动画直接跳帧到终态（状态变更照常发生） |
| prefers-contrast | `--fg-3` 提亮到 `--grey-9`，边框全部上调一级 |
| 语义 | 计时器 `aria-live="off"`（避免每 10ms 播报）；状态变化区 `aria-live="polite"`；日志区 `role="log"` |

## 3 · 字体

### 3.1 字体选型与理由

品牌声音三词：**冷静、精密、有摩擦感**。物理对象：体育馆翻页计时牌 / 秒表机芯。

| 角色 | 字体栈 | 理由 |
|---|---|---|
| `--font-display` | `"Barlow Semi Condensed"` → `"Noto Sans SC"` → `"PingFang SC"` → `"Microsoft YaHei"` → sans-serif | Barlow 的血统是加州公路标牌与公交标识字体（工程标牌感），Semi Condensed 变体的紧凑比例正好适合 18 个按钮的密集矩阵；它不是 Inter / DM Sans / Outfit / Space Grotesk 这套被用滥的选项。半压缩的拉丁字宽与中文方块字的密度更接近，中英混排时视觉节奏不会断裂。 |
| `--font-body` | `"Barlow"` → 同上中文回退 | 正文用常规比例，保证长句可读 |
| `--font-mono` | `"JetBrains Mono"` → `"SF Mono"` → `"Cascadia Mono"` → ui-monospace | 计时器 / 步数 / 日志 / 题目 ID / kbd 角标 / 按钮标签全部用它。选它的三个硬原因：① 真 `tabular-nums`；② 斜杠零，`0` 与 `O` 不混；③ 撇号 `'`（`U'` 记法的核心字符）与 `1` 有明确区分 |

**被考虑后否决的选项**：

| 候选 | 否决原因 |
|---|---|
| 编辑排版风（展示衬线 + 斜体 + 小型 mono 标签） | 这是 2026 年被 AI 工具默认用滥的美学路线；而且 Product 寄存器明确禁止 Dashboard 用 Serif |
| Martian Mono 作计时器 | 观感最贴「计时牌」，但字宽过宽，`1:42.37` 在 40px 下会占 260px+，左栏放不下 |
| Inter 作 display | 反射拒绝列表；且它的字腔过于圆润，缺工程感 |
| 系统默认字体栈直出 | 专家团红线 3，禁止 |

| 级别 | 字重 | 用途 |
|---|---:|---|
| Read | 400 | 正文、说明、日志 |

- 正文 `0`
- 中文不额外加字距（中文加字距会破坏方块字的等距美感）

### 3.4 数字排版（计时器的核心问题）

**问题**：`0` 到 `9` 宽度不等会导致每 10ms 数字跳动时整行左右抖动。

**方案**：

```css
.timer {
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums;   /* 等宽数字 */
  font-feature-settings: "tnum" 1, "zero" 1;
  min-width: var(--timer-min-w);        /* 7ch：容纳 99:59.99 */
  display: inline-flex;
  justify-content: flex-end;            /* 右对齐，位数变化时向左生长 */
}
.timer__int  { font-size: var(--timer-int-fs);  letter-spacing: var(--tracking-mono); }
.timer__frac { font-size: var(--timer-frac-fs); color: var(--fg-2); }  /* 小数位小一号 + 降一级灰 */
```

小数位用小一号字 + 降一级灰，是从 csTimer 借来的做法：**视线只需要捕捉整数位，小数位是「精度」而不是「信息」**。这一条能让计时器在同等字号下显得更小、更不压迫。

**所有数值型 UI 必须带 `tabular-nums`**：计时器、步数、TPS、剩余时间、日志耗时列、Agent 调用耗时。漏掉任何一个都会产生宽度抖动。

## 6 · 蒙尘态设计

> 本章已被 [`../prd/05-dust-observation.md`](../prd/05-dust-observation.md) §8 重写约束：**蒙尘是「防误看」，不是「防逆向」**。视觉设计必须与这个诚实定位一致，不能用视觉营造「安全」的错觉。
> 另外 PRD §8.2 的验收项 **AC-16** 用的是**确定性探针**：按相机矩阵取「每可见面中心 1 点 + 每面 4 个内缩点（内缩 = 投影包围盒 25%）」，断言探针像素 vs `--cube-masked` 的 ΔE ≤ 2、且 vs 6 个贴纸色任一 ΔE ≥ 20。这一条直接否决了原设计的「贴纸凹槽 + 方向光 + 静态噪点」方案——它们都会让探针偏离 `--cube-masked` 超过 ΔE 2。下方 §6.1 与 §6.6 已按此重做。

### 6.1 视觉定义（结论，按 AC-16 重做）

| 维度 | 结论 | 否决的替代方案及理由 |
|---|---|---|
| 材质 | **单色平光实体（unlit / flat）**：不接方向光、不接环境贴图、`roughness` 无意义（因为不走 PBR）、贴纸与 cubie 用同一材质 | 哑光 PBR + 方向光 → 每个面亮度不同，画布像素颜色 ≥ 4 种，**违反 AC-16**；磨砂玻璃 → 有透明感，被读成「正在加载」 |
| 颜色 | `--cube-dust-base` = `#2B323C`（L\* 20.4）单色。与 `--bg-stage`（L\* 3.94）的亮度差足够大，立方体轮廓清晰 | 更暗的灰（L\* < 12）→ 与舞台融合，像「没东西」，反而更像加载失败 |
| 几何 | **保留完整立方体外形与正确透视**，贴纸不下沉、无凹槽、无网格 | 加凹槽/网格 → 产生明暗差 → 像素颜色 > 2，**违反 AC-16**。改由「透视轮廓 + 可交互」承担「这是魔方」的信息（见 6.2） |
| 纹理 | **无纹理、无噪点**（原 `--cube-dust-grain` 作废） | 任何噪点都会产生大量中间色 → **违反 AC-16** |
| 动画 | **完全静止**。无呼吸、无扫光、无 shimmer | 这些是 loading 的强语义符号，一旦出现，任何文案都救不回来 |
| 禁止 | 禁止骨架屏 shimmer、spinner、进度条、动态噪点 | 同上 |

> `design-tokens.css` 中的 `--cube-sticker-edge` 在蒙尘态**不应用**（它会引入第二种颜色）。`--cube-dust-grain` / `--cube-dust-rough` 两个 token 标记为**保留不用**，Phase 3 实现时不得读取。

### 6.2 为什么不会被误读成加载失败（三条独立保障，全部在 3D 层之外）

AC-16 把「实体感」这条路封死了（像素颜色 ≤ 2），所以反误读的负担**全部转移到 UI 层**。这反而更可靠，因为文案是可验证的。

| 保障 | 具体做法 | 为什么有效 |
|---|---|---|
| **1 · 可交互性（最强）** | 蒙尘态下**鼠标拖拽旋转视角仍然可用**，方向键也仍然有效（视角旋转不泄露任何颜色信息，PRD §7.1 明确视角 0 步） | 加载中的东西**不会跟着你的鼠标转**。这是唯一一个「行为层」的信号，无法被任何视觉风格伪造 |
| **2 · 明亮的主 CTA** | 魔正方下方悬浮白实心按钮 `开始挑战`（`--action` / `--elev-3`）+ 一行 `按 Space 开始` | 加载失败的界面不会给你一个明亮的主按钮。且 `Space` 与 PRD §5.3.4 一致 |
| **3 · 「已生成」语义** | 左栏状态徽章 `待开始`（`--badge-pending-*`）+ 一行 `题目已生成 · 观察已锁定 · 题面 ID cb3-7f21a9` | **「已生成」与「加载中」是互斥语义**。给出具体 ID，等于宣称「数据已在内存里，只是不给你看」 |

补充第四条（次要）：**视角条、面视按钮、打乱/重置、操作矩阵 tab 全部可见且可点**（点击后按 PRD 返回 `NOT_STARTED`，UI 侧捕获后不报错，只在状态栏显示 `挑战未开始`）。满屏可点的控件是「已就绪」的强暗示，而 loading 态通常是灰掉或半透明的。

### 6.3 蒙尘材质的复用（统一视觉语言）

同一种 dust 材质必须复用到「当前未授权观察的面」，用于：

| 场景 | dust 应用范围 | 依据 |
|---|---|---|
| `ready`（待开始） | 全部 6 面 | PRD §8.2 C2 |
| 单面观察模式进行中 | 除当前授权面之外的 5 面 | PRD §8.2 C6 |
| 三面观察模式进行中 | 除当前朝向三面之外的 3 面 | 同上 |
| 受限观察（次数用尽） | 全部 6 面（视觉上回到待开始，但状态徽章是 `观察受限`） | — |

这样「蒙尘」这个视觉符号在用户心里只被定义一次——**「这块我不能看」**。它同时覆盖「挑战还没开始」和「这个面没授权」，不需要第二套视觉语言。

**注意 AC-16 只约束 `ready` 态**。`running` 态下单面/三面观察时，画布里必然有真实颜色（已授权的面），所以那里不受像素数限制，dust 材质与彩色贴纸可以共存。

### 6.4 解锁转场（600ms，但仍受 AC-16 与 reduced-motion 约束）

点击 `开始挑战`（或按 `Space`）后的转场：

| 时间轴 | 事件 | 参数 |
|---|---|---|
| 0–80ms | CTA：`--action` → `--action-hover`，`scale(0.98) → scale(1)`，文字淡出；同时 `status` 由 `ready` 切 `running`（门控在此刻打开） | `--dur-instant` |
| 0–400ms | 6 个面的 dust 材质**按面序 U → F → R → D → B → L 错峰 40ms**，各自 `160ms` 内从 `--cube-dust-base` 插值到真实色 | 单面 160ms / `--ease-out` |
| 0–400ms | 同步把着色模型从 `unlit` 切回 `PBR`，环境光 `0 → 1.0` 线性推进 | 400ms / `--ease-out` |
| 400–600ms | 一次性高光掠过（specular sweep，左上到右下，峰值强度 0.15），结束后移除临时高光对象 | 200ms / `--ease-standard` |

三个设计考量：

1. **不做噪声溶解。** 原设计的「噪声溶解遮罩」会在画布上产生大量中间色，与 AC-16 的验收思路（像素可控）冲突，且 4 阶 96 张贴纸的 alphaTest 溶解在移动 GPU 上会掉帧。改为**逐面颜色插值**，同样有仪式感，成本低一个数量级。
2. **按面序错峰 40ms** 保留。这 240ms 是在买认知：让观众能数出「六个面」，理解「这是一个六面魔方」，而不是「一大块颜色突然出现」。
3. **首帧 80ms 就有反馈**（按钮态 + 光照起点），用户不会二次点击。

`prefers-reduced-motion` 下：全部替换为 **150ms 不透明度交叉淡入**，无错峰、无高光。

### 6.5 与 PRD 门控约束的对接（设计侧必须遵守的 4 条）

> **视觉不能替代门控。** dust 是「状态的可视化」，不是「状态的保护」。原稿写的「由服务端强制执行」错误——本产品**没有服务端**（PRD §8 开头明确）。正确的边界如下：

| # | 约束 | 设计侧的责任 |
|---|---|---|
| 1 | `ready` 态 `observe()` 返回 `NOT_STARTED`，响应体不含 `face_colors` / `state_hash` / `scramble` / `seed`（C1） | dust 材质的颜色**只能**来自 `--cube-dust-base` 常量，**不得**来自 challenge 数据。这样即使有人翻 DevTools，材质里也没有真色可读 |
| 2 | `ready` 态不渲染任何带颜色的贴纸网格，画布像素颜色 ≤ 2（C2 / AC-16） | 见 §6.1，已按此重做 |
| 3 | `ready` 态**常驻**一行诚实文案（C5 / AC-17） | 位置：魔方遮蔽体正下方 24px，`--text-sm`，`--fg-3`，**不用警示色**。全文：「开始前不显示题面。本模式用于防止误看，不能阻止通过开发者工具读取内存。」与 CTA 上下排列，CTA 在上（先看到出口，再看到边界） |
| 4 | 蒙尘开启时的结果页脚注（PRD §9.2） | 「本模式用于防止误看，不能阻止通过开发者工具读取内存。」放在结果面板最底部的诚实标注区，与「本机测量，未经服务端校验」并列 |

**文案层级判断**：C5 的坦诚文案会削弱「仪式感」，但这是**必须付的代价**——PRD §8.4 明确要求「这段结论应同时出现在 PRD、结果页脚注、配置页蒙尘开关旁」。设计能做的是**降低它的视觉权重**（`--fg-3`、无边框、无图标、字号 12px、与 CTA 有 24px 间距），而不是隐藏它。

### 6.6 AC-16 的判定方式（已改为确定性探针）与遮蔽色实测

> **本节只承认一种口径：AC-16 确定性探针。**
> **历史口径（已作废，不作为任何判定依据）**：本文档早期写过「画布中心 80% 区域内、丢弃占比 <2% 的过渡色后，除背景外颜色种类 ≤2」。它被弃用的原因有二：① **魔方轮廓的边缘仍然落在中心 80% 区内**，收窄区域并没有把出问题的像素排除掉；② **「80%」把判定绑在布局比例上**，窗口尺寸/像素比一变就漂，验收结果不稳定。此外「边缘在哪、多宽」本身不可执行。
> **自查声明**：全文「80%」「丢弃占比」「颜色种类数」三个说法**只出现在本段历史说明与附 C 的审计记录里**，任何判定项（§9 A19 / B9）都不使用它们。凡见到它们出现在别处，按残留处理。

#### 6.6.1 判定方式（PRD v1.5，已冻结）

| 项 | 规则 |
|---|---|
| 探针取点 | 每个可见面 **中心 1 点** + 每面 **4 个内缩点**（内缩量取该面投影包围盒的 25%） |
| 断言 ① | 探针像素与 `--cube-masked` 的 **ΔE ≤ 2** |
| 断言 ② | 探针像素与 6 个贴纸色的 **ΔE ≥ 20** |
| 2D 降级视图 | 同样适用，用 6 个网格面的中心作探针 |

设计侧因此多了两条硬约束：
1. **遮蔽材质必须 unlit 且不做 tone mapping**（`toneMapping = NoToneMapping` 或对该材质禁用）。否则 PBR/ACES 会把 `--cube-masked` 渲染成另一个色值，断言 ① 的 ΔE ≤ 2 直接挂。
2. **`--cube-masked` 与 6 个贴纸色的距离是被测指标，不是主观选择。** 见 6.6.2 实测。

#### 6.6.2 遮蔽色实测：`#2B323C` 通过，且余量很大

要求「与 6 个贴纸色 ΔE ≥ 20」。实测（CIEDE76，与 PRD 口径一致）：

| 贴纸色 | ΔE vs `#2B323C` | 判定 |
|---|---:|---|
| U 白 `#F4F7FB` | 76.76 | 通过 |
| D 黄 `#F5C93C` | 100.42 | 通过 |
| F 绿 `#3DCE80` | 84.70 | 通过 |
| L 橙 `#F5821F` | 95.03 | 通过 |
| B 蓝 `#5484EC` | **63.85**（最差） | 通过 |
| R 红 `#CB3A36` | 76.22 | 通过 |

**最小 ΔE = 63.85（B 蓝），是阈值 20 的 3.2 倍。** 不需要调色。

一个反直觉的点：最危险的不是「灰白遮蔽色 vs 白贴纸」（ΔE 76.8，差得远），而是**「蓝调遮蔽色 vs 蓝贴纸」**——因为深色竞技风的遮蔽色天然会带一点冷蓝，而六色里正好有一个蓝。`#2B323C` 带的是极低饱和的冷灰（a\*≈-1.5, b\*≈-5.3），离 F 绿和 B 蓝都还远。**如果将来有人想把遮蔽色调成「更深更蓝」（比如 `#1E2A44`），第一个该测的就是它和 `#5484EC` 的 ΔE。** 这条我写进了 token 注释。

#### 6.6.3 剪影对比度：1.49:1，是刻意压低的

`#2B323C` 对 `--bg-stage`（`#0B0E14`）只有 **1.49:1**。这看起来偏低，但它是刻意选的：

| 选项 | vs stage | 问题 |
|---|---:|---|
| `#2B323C`（现值） | 1.49:1 | 剪影偏弱，但 CTA（`#EDF1F5`）对它是 **11.39:1**，主按钮仍是画面最亮的东西 |
| `#3A4152` | 1.89:1 | 剪影更清楚，但会亮过 `--bg-float`（L\*18.3），成为画面上除了 CTA 之外最亮的大色块——**在 `ready` 态跟主按钮抢注意力** |

**决策：保持 `#2B323C`。** 理由是这一屏的视觉优先级应该是「CTA 最亮 → 魔方剪影次之 → 背景最暗」，剪影只要「看得出有个立方体」就够，不需要「看得清每个面」。把它提亮会让 CTA 不再是唯一的焦点。

**已批准的 fallback（若真实截图里剪影读不出来）**：改 `#3A4152`（1.89:1，ΔE 最差 56.48 仍远超 20）。这是**一个 token 值改动，无其他联动**——所以先上截图看，不预设调。

#### 6.6.4 遮蔽态是纯色剪影 —— 确认「不加」体积线

架构问：unlit 单色材质会让遮蔽态完全没有体积感和倒角，就是一个纯色剪影；是否放宽到 3 色、加一条极浅的轮廓线？

**裁定：不加。** 三条理由：

1. **轮廓线本身会泄露「缝在哪」。** 而这个平台在 `ready` 态泄露 cubie 缝隙的位置，等于泄露「块有多大」——那是题面结构信息的一部分。一条「极浅的轮廓线」看着是美学妥协，实质是蒙尘边界上的一个洞。
2. **探针法下 3 色更难稳。** 2 色只需保证「遮蔽色 vs 背景」「遮蔽色 vs 6 贴纸色」两组距离；加第三种轮廓色就要保证它与前两者、与 6 个贴纸色、**以及在抗锯齿过渡带里**都可区分。这是把一条断言变成一组需要调参的规格。
3. **反误读不靠体积感，靠行为。** §6.2 三重保障里最强的一条是「蒙尘态能拖拽转视角」——加载中的东西不会跟着鼠标转。

不违反 2 色的三条补偿（都在 3D 层之外）：透视轮廓本身够读出立方体；画布 `min-h 420px`、魔方约占 55% 面积（**大**本身是「实物」暗示）；白实心 CTA + `题目已生成 · 观察已锁定 · 题面 ID ...` 的具体文案。

#### 6.6.5 不依赖投影分块（架构告知 shadowMap 默认关闭）

`shadowMap` 关闭后不许用投影区分块与块。分块由两条 CSS 变量承担：
- `--cube-sticker-gap: 0.06`（缝隙比例，架构已按此取值）
- `--cube-sticker-edge: rgba(255,255,255,0.10)`（贴纸内描边 1px，防止 R 红在深底上丢轮廓）

> **`running` 态的「块感」100% 来自缝隙 + 内描边**，没有任何阴影帮忙。所以这两个 Token 不是可调装饰，是结构线。**任何想调大 `--cube-sticker-gap` 的改动都必须先评估：缝隙变大 = 贴纸变小 = 4 阶单张贴纸（默认视角约 28px）可能跌破 18px，跌破后 §2.5.3 的字母标记就无法渲染。**

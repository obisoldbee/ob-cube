## 二、修复的 3 个问题

1. **「再挑战一次」在 seed/题库来源下退化成「同题面重跑」**（违反 v1.9 #43）
   - 现象：URL `?seed=` 或题库来源时，`retryNew()` 经 `resolveSeed()` 复用同一 seed，浏览器实测 challenge_id 与初始指纹完全相同。
   - 修复：`src/wiring/index.ts` `retryNew()` 不再解析 seed，强制交给会话层高熵随机。
2. **AC-44 限流（RATE_LIMITED）未实现**（PRD §16.3 明确保留在范围内）
   - 修复：`contracts.ts` 补 `E_RATE_LIMITED` 错误码；`session.ts` 新增帧计数限流（`beginFrame()` 由 wiring 的 rAF 循环与 250ms 兜底 interval 清零，同帧第 61 次 applyMove 抛错、不改状态不计步）。曾尝试 16ms/100ms 时间窗，均因每次调用的 O(n) UI 同步成本导致窗口滑出判据恒假，最终按 PRD 字面语义改为帧计数。
   - 附带：清理 `shared/errors.ts` 中 v1.2 遗留的「计时仍在进行」过时文案（与 v1.9 冻结语义矛盾，且无消费方）。
3. **F11「历史运行列表」UI 缺失**（PRD P0 / SPEC P0；`HistoryService.list()` 此前无任何消费方）
   - 修复：新增 `src/ui/panels/history-panel.ts`（最近 5 条倒序、§9.3 空状态与损坏记录「删除该记录/导出原始数据」处置），接入 shell 右栏与 wiring（落盘后/启动时刷新），补样式与 6 条单元测试。

修复后：vitest 205 条全过（新增 11 条）、`tsc --noEmit` 通过、浏览器回归确认三项修复生效且键盘/归并/暂停主流程无回归。

## 二、坐实的实现问题（未改动代码，待修复裁决）

### D1（AC-05 / ARCHITECTURE v1.4 §MoveEvent）：`layer_set` 暴露的是引擎 0 基轴索引，不是契约要求的记法层号

- 契约：ARCHITECTURE.md L914 明确 `layer_set: number[] // 记法层号，1-based，从被命名面算起，升序（AC-05：4 阶 Rw → [1,2]，3Rw → [1,2,3]，2R → [2]）`（v1.2 修订记录亦声明"layer_set 用记法层号"）；PRD §7.1/§5.7 同口径（1 起，从被命名面算）。
- 实测（`applyMove` 返回值与 `Run.events` 同源）：

| 输入 | 实测 `layer_set` | 契约要求 |
|---|---|---|
| 3 阶 `R` | `[2]` | `[1]` |
| 3 阶 `M`/`M'` | `[1]` | `[2]`（中层） |
| 3 阶 `B2` | `[0]` | `[1]`（出现 0，越出 1 基定义域） |
| 4 阶 `R` | `[3]` | `[1]` |
| 4 阶 `Rw` | `[2,3]` | `[1,2]` |
| 4 阶 `L` | `[0]` | `[4]` |
| 4 阶 `2-3R` | `[1,2]` | `[2,3]` |
| 4 阶 `3Rw` / `2R` | `[1,2,3]` / `[2]` | 恰好重合 |

- 根因：`session.ts` L499/L522 取的是 `spec.layerSet`（引擎原语的"轴索引集合，从负侧数，0 基"，notation.ts L38/L254），而解析器里已有符合契约的 `spec.layerIndices`（"记法层号，1-based，从被命名面算起"，L41）未被使用。
- 影响：外部 Agent 按 PRD/架构文档消费该字段会转错层；AC-05 的字面断言部分失败；`layer_count` 不受影响，HTM-layer 重算不受影响；事件流与 API 同源一致，回放自洽。
- 建议：`MoveResult.layer_set` 与 `RunEvent.layer_set` 改为 `[...spec.layerIndices]`（一行级改动），补 3 条单测锁定 3 阶 `R`→`[1]`、`M`→`[2]`、4 阶 `Rw`→`[1,2]`。

### D2（PRD §13.4/§13.1/§13.3）：持久化记录缺 5 个契约字段

对 `ob-cube:v1:run:<id>` 记录（结构 `{id, savedAt, result:{rules, status, …, events}}`）与事件对象的核查：

| 字段 | 契约位置 | 现状 | 影响 |
|---|---|---|---|
| `MoveEvent.input_channel` | §13.4（keyboard/button/api） | **src 全局零命中**，事件对象无此键 | 无法从记录区分人机输入来源；§11.1 埋点 `move_made.input_channel` 同受影响 |
| `Challenge.gen_version` | §13.1 可复现四件套 | 零命中 | 同 seed 在算法升级后无版本锚点，违背"缺任一项历史记录降级为不可验证"的自我要求 |
| `Run.engine_version` | §13.3、§10.4 | 结果页有「引擎 ob-cube 1.0.0」字样（UI 常量），**不入记录、无 AC-50 比对逻辑** | 旧记录回放兼容性提示（AC-50）无从实现 |
| `Run.metrics.htm_layer_count` / `qtm_count` | §13.3 | 结果页即时计算展示（AC-49 满足），不入记录 | 后验重算需重放事件，跨 run 对比表（F13）无现成列 |
| `Challenge.state_fingerprint`（位于 challenge 对象） | §13.1 | 以 `result.initial_fingerprint` 平铺存在（16 hex，长度达标），语义等价 | 仅形态差异，不算缺陷 |

- 说明：`rules` 内含 `seed` + `notation_version`（ss-2）+ `initial_fingerprint`，"重放打乱 + 指纹校验"的可复现链路在缺 `gen_version` 的情况下仍勉强成立，但版本漂移将不可检测——这正是四件套要求 `gen_version` 的原因。

## 三、PRD 自身问题（建议修订，非实现缺陷）

1. **AC-03 字面数学不可满足**：`R·R'·R2 = R2 ≠ 恒等`（R=+1, R'=-1, R2=+2 mod 4，任意排序和均为 2）。
   "依次执行 R、R'、R2 后指纹回到初始"在任何实现上必假。实测引擎的正确闭环行为：
   `R→R'` 回初态（即 AC-04）、R2 自逆成立。附录 C AC-03 同文。建议改为
   「依次执行 `R`、`R'` 后指纹回到初始；`R2` 执行两次回到初始」。
2. **附录 C 冻结条目 AC-55/AC-56 未随 v1.9 更新**：附录 C 仍写「暂停期间 `elapsed_ms` 须继续累加」
   「暂停中超时须判 `timeout` 且标注"超时发生于暂停中"」（v1.2 语义），与 §14.8 的 v1.9 语义
   （冻结计时、暂停中不可能超时）直接冲突。实现遵循 §14.8（本轮 AC-55~57 实测通过）。
   建议按附录 C 自己的规则以追加/标注方式处理，消除文档内自相矛盾。

## 四、观察项（非缺陷，记录在案）

1. **API 错误风格**：PRD AC-42 字面要求返回含 `ok` 键；实现成功返回平铺字段（无 `ok`），失败抛 `CubeError`（`code`/`message`/`hint`）。且 `submitSolution` 未还原时**前两次抛 `E_NOT_SOLVED`、第三次返回 `{accepted:false, reason}`** ——同一失败模式两种表达，建议统一（PRD 字面是返回 `{accepted:false}`）。
2. **`rotateView` 畸形参数**：传 `{axis,direction,steps}` 等不合約形状时抛内部 `TypeError`（`areCollinear` 读 undefined），而非 `E_VIEW_ORIENTATION_INVALID` 类结构化错误。合法参数行为无碍，属输入校验鲁棒性。
3. **前缀×阶数不匹配的处理口径**：键盘 `3+D`（3 阶）/`2+D`（2 阶）不执行转动，状态栏显示「3 阶无 3 层宽转」「2 阶无宽转」——**可见拒绝而非静默丢弃**，实现自洽且用户体验合理；但 PRD §5.3.2 写的是前缀「忽略」（可读作"前缀忽略、面键照常提交 R"），AC-34/AC-69 均未覆盖该分支。建议 PRD 补一句裁决。
4. **错误码命名映射**：PRD §12.1 短名 → 实现码的对应并非"加 E_ 前缀"：`INVALID_MOVE`→`E_NOTATION_MALFORMED`、`TIMEOUT`→`E_DEADLINE_EXCEEDED`、`MOVE_LIMIT`→`E_MOVE_LIMIT_REACHED`、`RATE_LIMITED`→`E_RATE_LIMITED`、`PAUSED`→`E_CHALLENGE_PAUSED`、2 阶 `Rw`→`E_MOVE_COVERS_ALL_LAYERS`（AC-07 字面是 `INVALID_LAYER`）。PRD 已声明"实现以架构师命名为准"，属文档映射表需对齐，非功能缺陷。
5. **URL `time` 参数未按 §2.2 边界校验**：`?time=60000`（单位秒）= 1000 分钟 > 上限 180 分钟，被接受且倒计时显示 `999:59` 封顶。UI 配置路径有边界，仅 URL 旁路未校验。
6. **AC-72 的断言机制未按字面实现**：PRD 建议的 `data-layer-set` 宿主属性不存在；但同源性质由组件构造保证（转向按钮标签直接渲染 `describeMove(当前勾选)`、点击提交同一 spec），行为级验证通过（R6b）。若要机器断言可补 `data-layer-set`。

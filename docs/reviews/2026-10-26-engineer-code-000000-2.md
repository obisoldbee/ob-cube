## 二、修复的 2 个缺陷

### D1（AC-58 / P4'）：Agent 模式渲染并可用「暂停」按钮

- 现象：参与者=AI Agent、running 态，会话面板照常渲染「暂停」；点击后挑战真的进入 `paused`（徽章「已暂停」、`getProgress().status === "paused"`）。违反 AC-58「Agent 模式下界面必须不渲染暂停按钮」与 §7.2.1 P4'「暂停仅人类模式可用」。前两轮未切过参与者，从未覆盖。
- 根因：`ChallengeView` 没有 `participant` 字段，`SessionPanel` 只按状态渲染按钮；`session.pause()` 也无参与者概念。
- 修复：`ChallengeView` 增加 `participant`（wiring 从 `config.participant` 投影）；`SessionPanel` 在 agent 参与者的 running 态不渲染「暂停」（签名含 participant，人机互切触发重建）；wiring `pauseChallenge` 端口加双保险门控（agent 模式 toast 拒绝，任何路径不得置 paused）。
- 验证：新增单测 2 条（agent running 无暂停/人类照常、人机互切重建）；浏览器复验：人类 [暂停,结束] / Agent [结束]，人类模式暂停/继续链路回归通过。

### D2（AC-28）：状态翻转发生在只读 API 内部时 UI 永久滞留

- 现象：模拟 Agent 轮询 `getProgress()`，超时结算恰好发生在该只读调用内部的 `tick()` 里 → 之后 800ms（rAF 与 interval 都在跑）UI 仍是 running 态：徽章「进行中」、按钮 [暂停,结束] 可点、矩阵未锁 `.matrix--locked` 不存在、结果面板不出现，直到用户做下一次操作。违反 AC-28「不得等用户下一次操作才体现」。（首次发现于一次脚本中断后的现场，随后受控实验稳定复现。）
- 根因：wiring `tickAndSync()` 只比较**单次调用内**的 before/after；翻转若发生在 `getProgress()`/`observe()` 的内部 tick（两者都会 tick 且不带 `onMutate` 回调），渲染循环的快照永远看不到变化，`sync()` 再也不会被触发。
- 修复（双层）：
  1. agent 层：`observe`/`getProgress` 用 before/finally 检测内部 tick 造成的状态翻转，翻转即调 `onMutate()` → 宿主同帧 `sync()`（含结果面板、落盘、矩阵锁死）；
  2. wiring 层：新增 `lastSyncedStatus`（`sync()` 末尾更新），`tickAndSync()` 判据改为「调用内变化 ∨ 与上次已同步状态不一致」，兜住任何其他旁路翻转。
- 验证：新增单测 3 条（getProgress 翻转触发一次、observe 翻转触发、运行中轮询零触发）；浏览器复现脚本转绿：翻转后徽章「超时」、矩阵锁死、结果面板同帧出现。

## 三、记录在案的观察（非缺陷）

1. **结果面板整栏替换右栏**：`showResult()` 把观察/日志/Agent/历史面板全部换掉，仅 interrupted 结局提供「查看操作日志」返回；非 interrupted 结局要等「同题面重跑/再挑战一次」才恢复右栏。符合 PRD §2.2 步骤 5「右栏切换为结果面板」的字面，但与 §9.1「回放过程」按钮并存的历史可见性存在体验张力，建议 PRD/UIUX 裁决是否给非 interrupted 结局也加「查看操作日志」。
2. **ended 态切参与者后 Agent 面板不可见**：结果面板占栏所致（上条的同源表现），`再挑战一次` 后面板恢复且按参与者显示，行为自洽。
3. 沿用前轮记录的分歧不变：`finished` 态 Space 无动作、autoSubmitOnSolved 死设置、观察模式无配置入口、埋点未实现。

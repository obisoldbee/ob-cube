## 0 · 使用说明

### 0.1 判定规则

| 规则 | 说明 |
|---|---|
| 阈值容差 | **全部 `±0`**，即实测值必须与表中数字逐位相等。唯一的例外是 A14b（ΔE ≥ 20，带不等号） |
| 单位 | 长度 px，色值 `#rrggbb` / `rrggbb`，时间 ms，字号 px |
| 取数方式 | 优先读**计算样式**（`getComputedStyle`）与**元素尺寸**（`getBoundingClientRect`），不用肉眼估。只有 A14b 与 A19 需要读截图像素 |
| 「抓哪张图」 | 是**证据截图**的命名前缀。同一前缀多张时加 `-2` `-3` |
| 结论 | `通过` / `失败` / `未执行`。**空白 = 未执行**，不允许留空当作通过 |
| 失败必须带数 | 失败栏写「实测 11px vs 阈值 12px」，不写「间距不对」 |

### 0.2 证据文件命名

```
docs/reviews/evidence/<编号>-<短名>[-<序号>].png
```

例：`A01-tabs-4x4.png`、`A21-timer-running-2.png`、`A20-paused-agent.png`

### 0.3 前置条件（缺一不可，否则整组作废）

| 项 | 要求 |
|---|---|
| 视口 | 三种：`1920×1080`（≥1440 档）、`1366×768`（1280–1440 档）、`1280×720`（最小支持窗口） |
| 浏览器 | Chrome 最近稳定版；另需 Firefox 最近稳定版复跑 A17 |
| 缩放 | `devicePixelRatio = 1`（除非某条明确要求 2x） |
| 主题 | 深色，无用户覆盖 |
| 数据 | 固定 3×3 / 4×4 题面各一个（seed 固定，便于复跑对比） |
| 状态 | 每条按「抓哪张图」构造状态，不得用假数据顶替 |

### 0.4 收口条件

**A 组 27 项全部 `通过`** 才进入 B 组。任一项 `失败` → 进 fix list，修完只复跑该项与受联动影响的项，不重跑全组。

### A14a 的取数方式（本轮确定）

**结论：走测试构建注入，不在生产包挂调试接口。**

| 项 | 做法 |
|---|---|
| 读取方式 | `page.evaluate(() => window.__obcube_test?.materialColors())` → 返回 `{U:'f4f7fb', …}` |
| 注入条件 | 只在 `__TEST__` 编译标志为 true 时赋值。Vite `define` 注入，**生产构建该分支被 DCE 消除** |
| 前置校验 | 生产包必须做一次断言：构建产物中字符串 `__obcube_test` 出现次数 **= 0**（`grep -c` 结果 0）。这条并入 A14a 的通过条件 |
| 为什么不用 `window.cubeAgent` | 它按 AC-41 只暴露 8 个方法、不含对象型属性，拿不到 `THREE.Color`。这是**正确的隔离**，不能为测试破坏它 |
| 为什么不改架构 | 若为测试把场景挂到 `window`，AC-41 与 AC-64 就破了——**为了通过一条验收去破坏三条验收，是负收益** |

## 附录 2 · 失败处理规则

1. **失败项只写三件事**：编号 / 实测值 vs 阈值 / 证据文件名。不写形容词。
2. **联动复跑**：某条失败并修复后，必须复跑「引用同一 Token 或同一组件」的条目。联动表：

| 改动 | 需复跑 |
|---|---|
| 任何 spacing Token | A8–A13、A03、A04、A05 |
| 任何色 Token | A14a、A14b、A15、A16 |
| 按钮尺寸 / 字号 | A6、A11、A21 |
| 结果面板结构 | A22、A23 |
| 蒙尘材质 | A19（+ B9 必须重跑） |
| 层选择器逻辑 | A7、A26（+ B10/B13 必须重跑） |

3. **A 组通过不等于设计通过。** A 组是「静态呈现对不对」；本产品约 30% 的价值在 B 组 15 条里（层描边、归并单调、暂停时间在跑、蒙尘可交互），它们**一张截图都看不出来**。A 组全绿只是入场券。
